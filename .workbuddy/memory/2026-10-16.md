## ecom-vision-mvp: 工作台页面设计复刻 ijihua.cn/workbench（收尾轮）

用户反馈"页面设计复刻还是有很多差距"，本轮用 Playwright(agent-browser) 对参考站做系统性取证后逐项关闭差距。

### 环境排障（耗时但有价值）
- 5173/3001 被用户的 **aigc 项目**（vite + nest start --watch）占用，ecom 服务必须换端口：
  后端 `PORT=3002`、前端 `VITE_PORT=5174 VITE_API_PROXY/VITE_API_BASE=3002`；vite.config.ts 与 main.ts
  已改为 env 驱动（默认值仍 5173/3001）。沙箱代理会把 localhost 302 成 502，curl 一律加 `--noproxy '*'`。
- 后端冷启动 ~25s（require @prisma/client 慢），不是卡死。
- **node 后台进程的相对路径坑**：Prisma adapter `file:./dev.db` 按 cwd 解析，在 workspace 根跑脚本会
  新建一个空 dev.db（已删）。脚本必须 cd backend 再跑。
- nest build 触发 safe-delete 钩子（dist 75 文件）被拦；改用 `npx tsc -p tsconfig.json` 直接编译。
- 后台进程的 broker IPC 会掉线（EPIPE "Broker closed without a response"），导致个别任务失败，重跑即可。

### 踩坑记录
- **className 串味**：HeroArt 拼贴 div 同时挂 `wb-hero-collage` 和调用方传入的 `wb-hero-art`，
  旧 `.wb-hero-art{width:420;height:auto}` 后置覆盖，导致拼贴 width 420/height 0（绝对定位子元素
  auto 高为 0）。修法：拼贴分支不再拼接外部 className。
- **hero 图裂**：recentTasks.thumbnailUrl 是相对路径 `/uploads/...`，浏览器按 Vite origin 解析 404；
  必须过 `toAbsoluteUrl()`。
- **浏览器 CSS 缓存**：agent-browser reload 不刷新 HMR 注入的 style，调试时用 `?cb=N` 强制全新加载。
- toAbsoluteUrl 返回 `string | undefined`，组件 props 类型要写成 `Array<string|null|undefined>`。

### 决策记录
- `size` 语义 = 长边目标、只缩不放（诚实）；matting 无 size 参数（参考站无，保源分辨率）。
- pitch = 逐行逆剪切 2D 近似（页面明示）；multi_fusion variantCount = 单图联络图单元数（参考站" N 张"
  语义在本地以一张联络图呈现，结果区明示占位）；sku_image 前端按 SKU 行拆 N 个任务。
- 参考站画布交互（涂抹/框选）→ 位置枚举 + 卡片披露；AI分析 → 信息提示条（不接入视觉模型）。
- 积分文案（0/5/40 积分）1:1 保留（参考站事实），本地无积分体系不校验。

### 踩坑
- 后台 bash 的 `cd ... && ` 前缀被系统从命令参数中剥离，命令在错误 cwd 执行（npx nest build 报找不到
  tsconfig.json）；workaround：`bash -c 'cd /abs/path && cmd'`。
- agent-browser `eval` REPL 跨调用累积 const 声明，重名报 Identifier already declared——每次换新变量名。
- 参考站 JSON.stringify DOM 节点触发 circular（captcha widget react fiber）——只收集纯字符串。
- jimp getBuffer 泛型联合类型 TS2349——用 `const img: Img = any` 别名。
- smoke 采样点落在间隙导致误失败（fusion space 布局取 4 个色块中心 ≥3 命中；sku bottom 用 1024*0.77=788
  而非 512*0.77=394）。
