**五个踩坑（重要，下次直接避开）**：
1. **媒体查询不增特异性**——@media 规则与外部静态规则按源顺序决胜：`.workbench{max-width:none}`
   被后方 `.workbench{max-width:1142px}` 反压（实测 hero 仍 1142），必须加前缀或删静态规则；
   `.wb-*` 移动栅格规则必须放全部 base 规则之后。
2. **inline style 压媒体查询**——侧栏宽度原由 JSX style 注入，任何 @media 无效；宽度类响应式必须 CSS 托管。
3. **「1:1 覆盖层」双刃剑**——置于区块后覆盖 token 值的静态规则会把同区块前面的响应式断点
   静默压死（.wb-tools 6 列从 1280 压到 390，卡 14px）。覆盖层只覆盖「值」不重复「结构属性」。
4. **html[data-promo] 是跨组件契约**——隐藏促销条必须同步置 off，纯 CSS display:none
   会让 pk-workspace / 多图融合高度算错 40px。
5. **本地后端登录有 ip 限流**——多 context 连登第 5 次起 429；多视口验证用单 context +

## 支付/积分/订单/商品 功能设计（docs/commerce-design.md）

关键裁定：
1. **积分不是单一余额，是批次账本** `CreditLot`(有 expireAt) + `CreditLedger`(只追加)。依据：订阅积分分月发放且有有效期（季卡"90天，每月发放"、周卡 7 天），加油包永久。扣减按 FEFO。

7. 新增 6 表：Product / ProductCapabilityPrice / Order / OrderItem / CreditLot / CreditLedger。OrderItem 全字段快照防改价影响历史订单。

**发现的 3 处现存冲突（P0，需裁定）**：
- 冲突 A：单任务积分价三套口径。6 个工具页硬编码「消耗5积分」、多图融合 40、SKU 图 0；而商品页价目反推是 **10 积分/图**（加油包 100积分=10张图、季卡 1100=110张图、全量包 2000=200张图）。5/40/0 与 10 互斥。

- 冲突 C：「限时免费」（抠图/去水印）与「消耗0积分」（SKU图）语义不同，塞进一个 cost 字段会丢失"限时"语义 → 建议 cost=0 + 后台 freeWindowEnd。

**裁定建议**：价目以 LandingPage 实拍价为准；消耗价 10/20/0（多图融合双输入=20，原 40 待确认）。

## 后台界面设计（docs/admin-ui-design.md，页面视角）

用户指令「页面视角设计」→ 产出界面设计文档（1404 行，20 章），未动代码。**PRD（做什么）→ 详细设计（怎么做）→ 界面设计（长什么样）三层分离**。

**§0 设计原则（6 条）**：令牌复用（不新增裸 hex）· 密度优先（后台工具，行高 44px）· 少装饰 · 操作可见 · 状态可辨 · 反馈及时。

**已核验令牌体系**：`global.css` 的 `:root` 内有 **263 个 token**，含完整圆角（radius/control/card/panel）、阴影（shadow-card）、文字四级（strong/body/muted/desc）、边框两级（border/border-row）。后台 UI 设计**全部复用，零新增硬编码**—— 逐个 hex 反查 global.css 确认存在（#5546d8 出现 22 次等）。

**每页统一结构**：ASCII 线框图 → 元素规格表 → 交互规则。

**关键设计决策**：
1. **菜单按权限过滤而非禁用** —— 无权项不渲染。禁用会让用户困惑"为什么在这里又点不动"
2. **操作列最多直显 2 个**，其余收「更多」下拉 —— 全铺开会让操作列宽到 400px 挤掉数据列
3. **详情一律抽屉 720px，不做嵌套** —— 关联对象跳转对应列表而非再开一层
4. **统计卡不上无意义趋势** —— 无对比期不显示 `↑0%`，制造噪音
5. **状态用颜色+图标+文字三重编码** —— 色觉障碍可达性
6. **已下架素材降透明度而非隐藏** —— 运营需看到历史
7. **退款/积分调整必须显示结果预览** —— 提交前看到扣多少、是否产生欠账
8. **已下架能力集中到页面底部灰区** —— 一眼看出哪些不可用，但不删行（避免误以为漏配）
9. **商品卖点改受控选项** —— 从源头杜绝无载体的承诺文案
10. **「按月发放」选项旁带警示** —— 明确告知无调度器会按一次性发放
11. **安全字段在导出表单显示但禁用** —— 让运营知道"有这个字段但不给导"，而非隐藏
12. **导入三步流程（上传→预检→确认）** —— 预检不写库，错误行可下载修正

**差异化呈现**：财务概览的「退款金额」下降趋势用**绿色**（退款少是好事），与「收入上升」配色逻辑相反 —— 语义优先于一致性。

**环境徽标**：仅非生产环境显示，防止误在生产执行测试操作。这是安全设计非装饰。

**不做（附录 C）**：移动端（<1024px 提示放大）· 嵌套抽屉 · 自定义列宽拖拽 · 主题切换（global.css 无 prefers-color-scheme）· 跨页批量选择。

**类名约定**：全部 `adm-` 前缀（.adm-layout / .adm-filter / .adm-thumb-grid 等）。

**文档层级（最终）**：
- `docs/prd.md` 整站产品需求 → `docs/admin-prd.md` 后台需求 → `docs/admin-detailed-design.md` 后台详细设计 → `docs/admin-ui-design.md` 后台界面设计

## 修复：后台布局错乱（用户报障「后台页面设计布局错乱」）

### 主 bug：antd Layout 默认 column 导致侧栏与内容重叠

**根因**：`AdminLayout` 用了 `<Layout className="adm-body">` 包侧栏和内容，但 antd 的 `Layout` 默认 `flex-direction: column`，**只有当子元素是 `<Layout.HasSider>` 时才切到 row**。我没用 HasSider，于是：
- `.adm-body` 没有声明 row → 侧栏与内容竖排
- 侧栏 `position: static` 无高度约束 → 只占内容自然高度，不铺满
- **内容区实际宽度 = 视口宽（1920），完全没扣掉侧栏的 240px** —— 侧栏浮在内容上方

诊断抓手（有效）：不用看截图也能发现 —— 打印 `.adm-sider` 和 `.adm-content` 的 `getBoundingClientRect().width`，若 `content === winW` 而 `sider > 0`，就是没扣宽度。

**修复**：
```css
.adm-body { display: flex; flex-direction: row; align-items: stretch; }
.adm-sider { position: sticky; top: 56px; height: calc(100vh - 56px); align-self: flex-start; }
.adm-content { flex: 1 1 auto; min-width: 0; align-self: flex-start; }
```
`.adm-sider` 的 sticky + `align-self: flex-start` 是关键：不加会让侧栏被 stretch 到超高（内容多时侧栏跟着长），或高度计算错误。

**修复后**：content = 1680 = 1920 − 240 ✓

### 次 bug：操作列平铺 5 个动作导致换行

`user.delete / reset_password / write / disable` 全平铺在 190px 列里 → 实测折成两行（行高 44→51px），且右侧被裁。
**这违背了我自己在 docs/admin-ui-design.md §2.3 定的「操作列最多直显 2 个，其余收进更多」原则** —— 设计文档写了，代码没照做。

修复：只留「详情」+「更多」，其余进 antd `Dropdown`（按权限过滤）；列宽 190→150；`.adm-row-actions` 改 `flex-wrap: nowrap` + `white-space: nowrap`。操作区高度从 51px → 20px。

### 新增布局回归测试（tests/admin-layout.spec.ts，6 例）
用**几何量测而非截图比对** —— 截图会被无关样式改动弄红，而这些是硬约束：
- `|content.left − sider.width| <= 2`（内容紧贴侧栏）
- `docW<= winW + 2`（无横向溢出），覆盖 1920/1440/1280 × 5 页
- 侧栏高度 == 视口 − Header，且 `overflow-y` 为 auto/scroll
- 操作区高度 ≤ 28px（换行会翻倍到 ~34px+）
- 直显动作数 ≤ 2
- 「更多」下拉至少 2 个菜单项

### 又一个测试陷阱：Playwright 用例间状态污染
「未登录访问后台」用例先 `page.context().clearCookies()` 再 `page.evaluate(() => localStorage.clear())` —— 但 page 还在 `about:blank`，localStorage 访问抛 SecurityError，清理不彻底 → **单跑通过、联跑失败**（被上一个用例的登录态污染）。
修复：先 `goto` 到同源页面再清 localStorage，并用 `waitForURL` 替代固定 `waitForTimeout`。

**联跑 13/13 全通**（admin.spec 7 + admin-layout.spec 6）。

### 经验
antd `Layout` 的 column 默认值是个隐形坑：`display:flex` 谁都会写，但**不写 `flex-direction: row` 就不是水平布局**。用 antd Layout 做自定义布局时，要么用 `HasSider`，要么显式声明方向。

## M16 数据安全：备份 / 恢复验证 / 保留期清理

按 admin-prd.md §3.19（B-96/97/98/100）落地。**已改产品代码**，闸口全过。

### 核心设计决策

**① 用 `VACUUM INTO` 而非 `cp`**
cp 在 WAL 模式下可能拷到写事务中间状态的撕裂库；VACUUM INTO 是 SQLite 官方一致性快照方式，在线完成且不阻塞读。已实测 `node:sqlite` 的 `DatabaseSync` 支持该语句。

**② B-97「无验证记录的备份视为无效」落到三处**
- service：`readForDownload` 对未验证返回 409
- UI：未验证行的「下载」是 `.adm-link.is-disabled` 灰色不可点（不是隐藏 —— 隐藏会让用户以为是 bug）
- 顶部告警条：有未验证副本就提醒"事故时可能无法使用"

理由：备份的价值全在事故那一刻兑现。未经校验的备份在出事时才发现损坏就晚了。

**③ 至少保留一份已验证备份**
`remove` 与 `prune` 都检查：删到 0 份已验证备份时返回 409。全删掉等于没有备份，比"备份过少"更糟。

**④ 清理目标白名单**
`CLEANUP_TABLES = ['AdminAuditLog','CleanupLog','BackupRecord']` —— **刻意不含 User/Project/Asset/GenerationTask**。用户原始素材属个人数据，需走注销流程匿名化，不能按时间批量删。订单受《电子商务法》3 年留存约束，更不能碰。
实测：传 `target:'User'` 被 400 拒绝。

**⑤ 调度器用轮询而非 node-cron**
启动后 5s 首检 + 每 10 分钟轮询，判定"今天是否已备份"（比对当天 succeeded 记录）。理由：本地单机部署无常驻进程保证，node-cron 错过执行后补跑逻辑更复杂；轮询行为可预测且便于测试手动触发。有重入保护（`running` 标志）与 `unref()`。

### 踩到的真bug：NestJS 路由按声明顺序匹配

`@Get('cleanup-logs')` 写在 `@Get(':id')` **之后** → 请求 `/cleanup-logs` 被当成 `id='cleanup-logs'` 查备份 → 返回 404。
排查手法很直接：直接 curl 该路径看返回什么，就知道是被 `:id` 吃掉了。
**规则：任何字面量路由（`stats` / `prune` / `cleanup-logs`）必须声明在参数路由 `:id` 之前。**已在代码注释里写明。

2. Playwright `getByText('已验证')` 在页面出现 3 次（统计卡标题/表格标签/告警文案）→ strict mode violation，需 `.first()`

## M5 素材管理 + 多存储后端（本地/OSS/MinIO）

用户指令「素材管理：本地/oss/minio」。按 admin-prd.md §3.4（B-21~27）+ §3.11（B-62/63）落地。闸口全过。

### 核心设计

**① 云SDK 按需 require，本地开发零云依赖**
`StorageService` 构造时才 `require('ali-oss')` / `require('minio')`，且只在对应环境变量齐全时才执行。未配置 → SDK 根本不加载。npm install 体积与启动时间都不受影响。

版本联网核实：`ali-oss@6.23.0`（2025-12）、`minio@8.0.7`（2026-02）。均未装进 package.json —— 需要时再装，避免本地开发被云 SDK 拖累。

**② Asset 必须记 storageBackend（关键设计）**
素材记录里存「写入时的后端」，读取/删除都按它走。不加这个字段，切换 `STORAGE_BACKEND` 会让**全部历史素材 404**。已实测：切换只影响新上传，老素材照常从原后端读。

**③ storageKey 是唯一真相，sourceUrl 只是展示**
DB 存 `generated/202610/xxx.jpg`，不存可变的完整 URL。切换域名/CDN 只需改配置，不必刷库。

**④ 下架 ≠ 删除（B-26）**
下架只改 `status`，文件与记录都保留，误操作可恢复；删除是另一个不可逆动作。管理端**不过滤** hidden（运营要能找到自己下架过什么），用户端过滤。

**⑤ 删除顺序：先删文件再删记录**
反直觉但正确 —— 记录删了就查不到 storageKey，文件会成为永久孤儿占磁盘。AdminAssetsService 与 AssetsService 都是这个顺序。

**⑥ provider 接口保持磁盘路径契约**
`ImageProvider.generate(capability, inputPaths, params)` 收的是路径（jimp 与网关SDK 都要）。改接口会波及全部 provider 实现。所以输入从存储层读出 Buffer 后**物化到临时目录**，产出走存储层，finally 清理临时目录。
> 这是有意识的取舍：接口稳定 vs 抽象纯粹。收益不抵成本。

**⑦ 路径穿越双保险**
`assertSafeKey()` 正则白名单 + LocalStorageProvider 二次校验 resolve 后仍在 root 内。

### 修掉的真实缺陷

**① 生成产出完全绕过存储层（真 bug）**
`generate.service.ts` 三处硬编码：`join(cwd,'uploads','generated',outName)`、`writeFile`、`sourceUrl`。导致 5 条新生成素材**没有 storageKey**，切换后端后必然丢失。已改走抽象层。

**② 素材列表 500：`take: "5"` 是字符串**
我用 `Record<string, unknown>` 当查询参数，**绕过了全局 ValidationPipe 的 transform**（它负责把 query string 转 number），pageSize 原样透传给 Prisma → `Expected Int, provided String`。
修法：`AssetListQueryDto` / `ProjectListQueryDto` 真正的 DTO 继承 PageQueryDto。
> 教训：NestJS 里 DTO 不只是校验器，还是类型转换器。用 `Record<string, unknown>` 顶替会静默丢掉转换。

**③ 存储状态接口漏返回未配置后端（产品缺陷）**
原本只返回已注册的 provider → OSS/MinIO 未配置时界面完全看不到它们，运营不知道存在、也不知道怎么启用。我写了「启用所需环境变量」的样式却永远渲染不出来。
修法：`ALL_BACKENDS = ['local','oss','minio']` 全量返回，未配置的 `configured=false`。缺失信息比多余信息更致命。

### 环境问题（非产品代码）

- **`class-validator` 被升到 0.15.1**（package.json 锁 0.14.2）→ Nest 报 `class-validator package is missing`。`npm ci` 失败，`npm install` 被 broker 拦截（safe-delete 拒绝 rename）。最终自然恢复。
- 排查弯路：Nest 用 `await import()` 动态加载包，而我用 `require.resolve()` 探测 —— 两条解析路径不同，差点误判成包损坏。
- `ProvidersModule` 的 `exports` 列了 `CapabilityRouterProvider` 但 providers 里只有 `useClass` 绑定 → `UnknownExportException`。改为显式注册 + `useExisting`（同实例，且可按类注入）。
