## 排查：/admin 报 `Failed to fetch dynamically imported module: AdminDashboardPage.tsx`

**结论：代码无缺陷，是 Vite dev server 依赖预构建缓存失效（Outdated Optimize Dep），属运行时状态问题。**

- 用系统 Chrome（Playwright，非 bundled chromium，本机缓存版本不匹配）/admin 稳定复现：
  - `HTTP 504 /node_modules/.vite/deps/@tanstack_react-table.js?v=357d1888`
  - `HTTP 504 /node_modules/.vite/deps/recharts.js?v=357d1888`
  - 浏览器把下游 504 统一报成顶层动态 import 失败，URL 带 HMR 时间戳 `?t=1793860786001`（14:39:46）。
- `frontend/node_modules/.vite/deps/` 目录整个不存在（只剩 `.vite/vitest/results.json`，14:07 写入；`.vite` 14:14 重建），而 dev server（PID 81636，Vite 8.3.4）仍在跑并向浏览器输出旧 `?v=357d1888`。
- 静态扫描 386 个 `/src` 依赖全 200/JS MIME，**扫描器当时漏掉了 `/node_modules/.vite/deps/*`，正好漏掉真凶** → 以后排查此类错误必须把预构建 dep URL 也纳入。
- 对照实验：独立 `cacheDir=/tmp/vite-verify-cache` 起临时 Vite 于 5101 + `optimizeDeps.force`，`/admin` 零 4xx、零 console error，AdminShell 正常挂载。
- 只有后台挂的原因：`recharts`/`@tanstack/react-table` 仅被 `src/admin-ui/primitives/{chart,table}.tsx` 引用，位于懒加载链，C 端首屏不碰。

**修复路径**：① 立即：重启 dev server（deps 已不存在，启动时会重新扫描生成一致 hash）+ 浏览器硬刷新清 `?t=`；② 防复发（待裁定）：`vite.config.ts` 加 `optimizeDeps.include: ['@tanstack/react-table', 'recharts']`，避免运行时发现新依赖触发 re-optimize；dev server 运行期间不要清理 `node_modules/.vite`。

诊断脚本留在 /tmp：`vite-graph-scan.mjs`（依赖图扫描）、`vite-admin-repro.mjs`（浏览器复现）、`vite-clean-cache-verify.mjs`（干净缓存对照）。
