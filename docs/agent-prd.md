## 1. 背景与定位

货觉AI 当前是一个**能力驱动**的平台：16 项能力（15 项图像 + 1 项视频）由 `capabilities/definitions/` 单一事实源定义，用户在 `/workbench` 里选能力 → 填参数 → 提交任务 → 轮询产出。

这带来一个明确的产品天花板：

| 现状痛点 | 用户视角 | 业务后果 |
| --- | --- | --- |
| 用户必须知道「该用哪个能力」 | 「我想给这个商品做一套图，但不知道从哪开始」 | 新用户首次使用即流失 |
| 参数表单是静态的 | 「背景换成高级灰，该填什么值？」 | 反复试错，任务失败率高 |
| 能力之间无串联 | 「主图、详情页、SKU 图要风格统一」需人工逐个做且难以一致 | 产出不连贯，复用价值低 |
| 无法用自然语言表达模糊需求 | 「帮我把这个商品做成小红书风格的整套图」做不到 | 需求覆盖不了真实业务语言 |

**AI 智能体**就是补上这一层：把「用户选能力填参数」升级为「用户描述目标，智能体规划步骤、调用能力、交付结果」。

### 1.1 三重定位

本需求明确包含三类能力，**不拆成三个独立产品，而是同一个 Agent 内核上的三种运行形态**：

| 定位 | 说明 | 典型场景 |
| --- | --- | --- |
| **内容创作型** | 电商视觉内容生产，直接复用现有能力清单 | 商品整套图（主图+详情+SKU）、风格统一批量出图 |
| **通用对话/任务助手** | 自然语言 → 意图识别 → 调用能力/查数据 → 执行 | 「我的作品里有哪些爆款复刻」「帮我查一下这个月的生成量」 |
| **工作流编排型** | 多步骤 DAG 编排，每步可由 LLM 决策或人工确认 | 从选品图到整套投放素材的端到端流水线 |

**统一内核的价值**：三者共用同一套 LLM 通道、工具注册表、上下文管理、积分计费与可观测性。差异只在「谁来决定下一步做什么」——LLM 决策（Agent 模式）、用户驱动（对话模式）、预定义模板（工作流模式）。

## 2. 目标用户与场景

### 2.1 用户画像

| 角色 | 占比预估 | 特征 | Agent 给他的价值 |
| --- | --- | --- | --- |
| 电商运营（小微/代运营） | 主要 | 会用工具，但不懂参数背后的技术含义，需求口语化 | 用自然语言直接拿到结果 |
| 电商老板/负责人 | 次要 | 只关心「做完没有、好不好看」，不碰工具 | 一句话下达目标，看进度与结果 |
| 设计师 | 次要 | 对风格一致性要求高，重复劳动多 | 锁定风格基准 + 批量套用 |

### 2.2 核心用户故事

**US-01 整套图生成（P0）**
> 作为电商运营，我上传一个商品图，说「做一套小红书风格的商品图」，得到风格统一的主图、详情图、SKU 图，而不是自己逐个填 15 种表单。

验收：单次会话内产出 ≥ 3 张图，视觉风格一致（同一 style lock），全部出现在「我的作品」。

**US-02 模糊需求澄清（P0）**
> 我说「背景换成高级灰」，系统不应直接猜一个值，而应反问我「深灰还是浅灰？用于主图还是详情页？」。

验收：Agent 在参数歧义时**必须**发起澄清而非猜测；用户可回答、可跳过（跳过则用默认值并明示）。

**US-03 工作流复用（P1）**
> 我把调好的一套流程存为「服饰类目整套图」模板，下次上传新商品图一键复用。

验收：模板可保存/命名/一键调用，团队内可共享。

**US-04 任务型对话（P1）**
> 我问「上周生成失败了几个任务，为什么失败？」，Agent 查库后给出结构化答案而不是让我去翻日志。

验收：只读查询类问题 Agent 直接答；写操作必须显式二次确认。

**US-05 产出可追溯（P0）**
> 每个 Agent 产出的图，我要能看出它用了哪个能力、什么提示词、花了多少积分。

验收：Agent 任务在详情页展示 steps 明细，与 `ModelCallLog` 打通。

**US-06 失败可控（P0）**
> 中间某步失败（网关挂了），Agent 要能告诉我失败在哪、能否只重跑这一步，而不是整条链路白跑。

验收：步骤级状态机；支持「从失败步骤续跑」，已成功步骤不重复消耗积分。

## 3. 功能范围

### 3.1 MVP 范围（P0，必须交付）

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F-01 | Agent 会话 | 会话/消息持久化，流式输出，停止/重试 |
| F-02 | 意图识别与规划 | LLM 将自然语言转为能力调用计划（可含澄清问题） |
| F-03 | 工具注册表 | 全部能力 + 查询类工具统一暴露为 Agent 可调用的 tool，参数 schema 化 |
| F-04 | 参数澄清 | 歧义参数反问用户，可跳过取默认 |
| F-05 | 风格锁定 | 会话级 style lock，保证多图产出风格一致 |
| F-06 | 步骤级执行与状态机 | 每个 step 独立状态，失败可单步重跑 |
| F-07 | 积分计费与退款 | 沿用 `CreditLedger`，Agent 沿用现有 `GenerationTask.creditCost` 语义；失败步自动退款 |
| F-08 | 来源如实标注 | 新任务 `provider` 恒为 `gateway`；无可用模型线路时如实失败并退款，不产出占位结果 |
| F-09 | 产出入库 | Agent 产出一律落 `Asset` + `GenerationTask`，进「我的作品」 |
| F-10 | 可观测 | 每次 LLM 调用写 `ModelCallLog`（复用现有表，新增 `channel: 'llm'` 区分） |

### 3.2 次期范围（P1）

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F-11 | 工作流模板 | 保存/复用/共享编排模板 |
| F-12 | 定时/批量 | 对多商品批量跑同一流程 |
| F-13 | 多智能体协作 | 策划/执行/审校角色分工（本期仅预留扩展点，不实现） |
| F-14 | Agent 配置后台 | 提示词、模型选择、温度等在 admin 可配 |

### 3.3 明确不做（Out of Scope，MVP）

- 不做 Dify/Coze 式通用低代码编排画布（成本高，与「整套图」主场景不匹配）
- 不新增音视频生成能力（视频侧只沿用现有图生视频这一项，不做 Agent 原生视频编排）
- 不做 Agent 自建代码执行（沙箱成本与安全风险高）
- 不做跨用户 Agent 市场

## 4. 交互设计要点

### 4.1 一次典型的 Agent 会话

```
用户：[上传商品图] 做一套小红书风格的商品图，主图要竖版

Agent：已理解，生成计划如下（4 步）
       ① 解析商品特征 → 卖点文案        [自动]
       ② 生成主图（竖版 3:4，小红书风）   [自动]
       ③ 生成 3 张详情图                 [自动]
       ④ 生成 SKU 图                    [待确认]
       预计消耗 12 积分，是否继续？
       [继续] [调整计划] [仅执行①②]

用户：继续

Agent：▸ ② 完成 → 产出图（真实模型 / 占位效果）
       ▸ ③ 进行中 ...
       ▸ ④ 已跳过
       [查看全部产出] [导出到项目]
```

### 4.2 关键交互原则

1. **计划先于执行**：涉及多步或消耗积分的操作，必须先展示计划并等确认。写操作绝不静默执行。
2. **如实标注来源**：每个产出标明来源。能力 `mode` 只有 `real` 与 `planned`，无可用模型线路时任务失败并退款，不产出占位结果。
3. **失败可见可续**：失败步骤高亮 + 一键重跑该步，不重跑全链。
4. **降级不空手**：LLM 通道不可用时，Agent 降级为「表单模式」引导用户手动选能力，而不是报错白屏。降级只换交互入口，不伪造产出——与现有「无模型线路即失败并退款」的口径一致。

## 5. 数据与计费

### 5.1 计费原则

- Agent **本身不额外收费**，只对实际调用的能力扣积分（复用 `GenerationTask.creditCost`）
- 计划被用户调整后，未执行的步骤不扣费
- 失败步骤自动退款，写 `CreditLedger`
- LLM token 成本本期**不向用户计费**，仅通过 `ModelCallLog` 做成本核算

### 5.2 数据留存

- 会话与消息持久化，支持历史回看
- Agent 运行记录保留 90 天，可配置
- 用户可删除会话（连带删除消息，产出图保留在作品库）

## 6. 非功能需求

| 项 | 要求 | 依据 |
| --- | --- | --- |
| 首字响应 | 流式输出，TTFT ≤ 3s（LLM 通道可用时） | — |
| 降级可用性 | LLM 通道全挂时功能降级但**不报错**，回到表单模式 | 与现有「无线路即失败退款、不伪造产出」口径一致 |
| 依赖纪律 | **不引入重型 Agent 框架**（LangChain 等），LLM 调用用轻量自研 | 项目依赖树纪律，`npm` 大批量安装会 5 分钟硬超时 |
| 版本锁定 | 所有新增依赖精确锁版本，无 `^`/`~` | `CLAUDE.md` 技术栈约定 |
| 可观测 | 每次 LLM 调用落 `ModelCallLog`，含耗时/token/成败/回落原因 | 复用现有表 |
| 风格一致 | 同会话 style lock 下产出风格一致（这是工作流编排的核心价值） | — |

## 7. 验收标准（MVP）

必须全部满足才算 MVP 达成：

| 编号 | 验收项 | 判定方式 |
| --- | --- | --- |
| A-01 | 用户输入自然语言，Agent 返回结构化执行计划 | 真实会话录制，非 checklist 自评 |
| A-02 | 计划经用户确认后执行，产出落 `Asset` 且出现在「我的作品」 | 查库 + 页面核对 |
| A-03 | 歧义参数触发澄清而非猜测 | 构造 3 类歧义输入验证 |
| A-04 | 步骤级失败可单步重跑，已成功步骤不重复扣费 | 断网/断网关场景实测 |
| A-05 | 无可用模型线路时 Agent 步骤如实失败并退款，不产出占位图 | 停掉通道实测 + 查积分流水 |
| A-06 | LLM 通道不可用时降级为表单模式，不 5xx、不白屏 | 停掉通道实测 |
| A-07 | 每次 LLM 调用在 `ModelCallLog` 可查 | 查库 |
| A-08 | 新增依赖通过 `npm run verify:deps:critical` | 闸口实跑 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| LLM 幻觉出不存在的能力 | Agent 调用失败或产生无效任务 | 工具 schema 由 `capability.registry.ts` 生成，模型无法编造能力 id |
| 多步执行积分超支 | 用户成本失控 | 计划阶段预估积分并展示，用户确认后才执行；每步独立扣减 |
| Agent 任务与现有任务体系割裂 | 作品库/统计/后台看不到 | 强制复用 `GenerationTask` + `Asset`，不新建平行任务表 |
| 风格一致性难保证 | 核心卖点失效 | style lock 作为显式参数注入每次调用，而非依赖模型隐式记忆 |
| 依赖安装超时 | 阻塞开发 | 轻量自研，零新增运行时依赖（LLM 走 `fetch`） |
| SQLite 并发写入压力 | 高并发会话下锁竞争 | Agent 消息批量写、单会话串行执行 |

## 10. 待评审确认项

1. **LLM 通道走哪个服务**：现有 `GATEWAY_BASE_URL` 网关是否提供 LLM（chat/completions）能力？若无，是复用网关还是直连第三方模型 API？
