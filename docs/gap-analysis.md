## 1. P0 · 监管强制缺口（3 项）

### GAP-01 账号注销与个人信息删除（最高优先）

| 项 | 内容 |
|---|---|
| 事实 | `backend/src/auth/dto/` 只有 `login.dto.ts` / `register.dto.ts`。**无 forgot-password、无 reset-password、无注销**。用户忘记密码即永久失号；想注销无处可注销 |
| 法规依据 | 《App 违法违规收集使用个人信息行为认定方法》第六条：未提供有效的更正、删除个人信息及注销用户账号功能，可认定为「未按法律规定提供删除或更正个人信息功能」；承诺时限不得超过 **15 个工作日**。另《个人信息保护法》第 47 条：撤回同意、停止服务、保存期届满等情形下应**主动删除** |
| 常见违规点 | ①设不合理条件（如强制清空作品、强制注销第三方账号 —— 上海网信办已列为案例）；②承诺时限超 15 工作日；③前台执行了后台没删 |
| 需补 | `DELETE /account`（用户自助注销，二次确认 + 影响面提示）；`POST /auth/forgot-password` + `POST /auth/reset-password`；`PATCH /account/profile`（更正姓名/邮箱）；`GET /account/export`（下载个人数据副本）；`/legal/account-rules` 增补注销与删除章节；后台「注销申请」队列 + 15 工作日 SLA 看板 |
| 数据处理 | 注销时 `User.status='deleted'` 软删 + **联动处理**：`Project`/`Asset`/`GenerationTask`/`CreditLot`/`Order`（订单不可删，电子商务法要求交易信息保存**不少于 3 年**）；`CreditLedger` 保留（财务凭证）；头像等可识别信息匿名化 |
| 归属 | 新增 `docs/account-compliance-design.md` 或并入总纲 |
| 优先级 | **P0，建议排在 M1 合规标识同一批次** |

> ⚠️ 与 GAP-02 的边界：订单属交易信息，受《电子商务法》第 31 条约束不得随注销删除，**必须明确写入注销说明**，否则用户会误以为"注销=全部删除"，构成告知不准确。

### GAP-02 AIGC 生成内容标识

| 项 | 内容 |
|---|---|
| 事实 | `backend/src` 零标识代码（已 grep 核实） |
| 法规依据 | 《人工智能生成合成内容标识办法》2025-09-01 已施行；显式标识 + 隐式元数据（字段名含 `AIGC`）；下载/复制/导出时文件必须含显式标识 |
| 已覆盖 | 总纲 §1 已完整设计，**未实现** |
| 优先级 | P0（M1） |

### GAP-03 敏感内容审核（涉政/涉黄/违法违规）

| 项 | 内容 |
|---|---|
| 事实 | 能力 `remove_watermark`（`capability.registry.ts:480`）撞《标识办法》第 12 条「不得为他人实施上述恶意行为提供工具或服务」；15 项能力无任何内容安全检测 |
| 需补 | 上传与生成双侧接入内容安全服务；未接入时**明示"未接入"**，不做假审核 |
| 已覆盖 | 总纲 §1.3「内容安全送审」P1、§1.3「去水印能力管控」P0 |
| 优先级 | P0（去水印管控）/ P1（内容送审） |

## 2. P0 · 商业闭环阻塞（4 项）

### GAP-04 定价裁定未落地 → 积分账本无法开工

三份设计都依赖同一个前置：**单能力消耗价**与**唯一价目源**未定（`commerce-design.md` §11 冲突 A/B）。
不定则 M6 账本上线即错账。**这是唯一真正阻塞开发的一项。**

### GAP-05 支付资质与对账

| 缺什么 | 说明 |
|---|---|
| 真实支付通道 | 无商户号。`commerce-design.md` 只做沙箱（§6.2） |
| **支付对账** | 沙箱设计里**完全没有对账模块**。真实接入后必须每日与渠道账单逐笔核对，差异需人工介入。这是财务闭环的最后一环，遗漏会导致账实不符 |
| 发票 | ToB 客户要发票，目前无发票类型/抬头/税号/开票记录 |
| 分账 | 若引入代理分销（M16），需要分账能力（commerce §6 席位 P2 已列但未涉及资金流） |
| 建议 | 沙箱阶段先做「模拟对账单」（手工导入渠道 CSV，比对内部订单），把对账逻辑跑通，真实通道接入时只换数据来源 |

### GAP-06 短信/邮件通道缺失 → 关键事件无法触达

| 事实 | `backend/package.json` 无 nodemailer/短信 SDK，grep 无任何触达通道 |
|---|---|
| 必须有的场景 | ①注册验证（当前注册即登录，无验证）②找回密码 ③订单支付成功 ④订阅到期提醒 ⑤违规处置通知 |
| MVP 建议 | 站内信先行（总纲 §4 已设计）；**找回密码必须先做**（GAP-01 依赖），可先用「管理员重置」兜底（admin 设计 §4.2 已有），但正式上线需邮件通道 |

### GAP-07 账号安全：无验证码/限流/风控

| 事实 | grep `throttle\|rate-limit\|限流\|防刷\|captcha` **零命中** |
|---|---|
| 风险 | 注册接口无频率限制 → 可被批量注册薅赠送积分（commerce 设计里新用户送 100 积分，是明确攻击面）；登录接口无限制 → 撞库；生成接口无限制 → 刷积分 |
| 需补 | 登录/注册/生成/上传四类限流；邮箱验证码；异地登录提醒；敏感操作二次验证 |
| 优先级 | **P0**（薅羊毛是上线第一天就会发生的） |

## 5. P3 · 架构级（4 项）

| # | 缺口 | 影响 | 建议 |
|---|---|---|---|
| GAP-27 | ~~**多租户 / 企业版**~~ | — | ✅ **本期不做**。`Organization` 等 4 表不建、`User` 不加 `orgId`、M16 批次取消 |

| GAP-29 | **图片存储用本地磁盘** | `main.ts:49` `useStaticAssets(join(cwd,'uploads'))` 直挂本地目录，**无鉴权** | ①迁 OSS/CDN（生产必需，否则磁盘与带宽必爆）②**当前任何拿到 URL 的人可直接访问任意用户素材**（UUID 难猜但 URL 一旦泄露即公开）——这是现存安全问题，与商业化的付费素材定位直接冲突 |
| GAP-30 | **暗色模式下的图表库** | antd 无内置图表 | 数据分析模块需引 ECharts/Recharts（与"优先成熟开源库"纪律一致） |

> GAP-29 是**现存安全缺陷**而非功能缺口：付费后素材是用户资产，"任何人可凭 URL 访问"不能接受。建议至少先做「签名 URL + 有效期」，再排 OSS 迁移。
