# 生图链路与提示词规范

状态：商品主图（`/product-kit`）与商品详情图（`/product-detail`）已实现；提示词效果评估（A/B）未实施。

本文用产品视角说明：用户填的表单如何变成模型的画面要求，以及一次提交为什么会产出多张图。逐字段技术契约见 [`main-image-generation.md`](main-image-generation.md) 与 [`product-detail-generation.md`](product-detail-generation.md)，通用提示词规则见 [`prompt-engineering.md`](prompt-engineering.md)；代码与本文冲突时以代码为准，并在同一次变更中修正本文。

## 1. 一次提交，多张图

```text
商品图 + 商品信息 + 生成设置 + 商品描述 + 类型 / 模块勾选
                          ↓
                 用户点一次「生成」
                          ↓
        系统按主图类型或详情模块拆成 N 张图
                          ↓
   每张图各自计费、各自生成、各自失败与退款（同批共享批次编号）
                          ↓
              结果页聚合成「一次生成」展示
```

五条产品规则：

- **一次提交只发一个请求**，拆单在服务端完成。用户只表达「要哪几类、各几张」或「勾了哪些模块」。
- **每张图各扣一次能力单价**：主图四类与详情图各模块当前均为 10 积分/张（以后台现行售价为准），同能力内不按版式差异定价。
- **一张失败不连累同批**：每张图有独立的账单与退款路径，不会出现整套没出却只退一张钱。
- **商品图是真实参考素材，不是一句文字描述**：系统把上传的图直接交给模型，画面要求只补充参考图张数与商品一致性约束。
- **模型选择只影响线路**：用户选的模型分组不进入画面要求，组内走哪条线路由系统决定，切换线路不改价格。

## 2. 商品主图

### 2.1 四类图，各管一件事

| 主图类型 | 画面目标 | 文字策略 |
| --- | --- | --- |
| 白底图 | 纯白无缝背景，无投影、无渐变、无场景道具；商品居中完整呈现，正面或微侧 45° 视角 | 不写字 |
| 场景图 | 商品置于与品类相符的真实消费场景，光线自然、道具克制，商品为唯一主体 | 不写字 |
| 卖点图 | 一图讲清一个卖点；商品占画面 45%–60%，其余区域用简短文字与图标标注 1–3 个卖点 | 可写字，但只能用用户提供的事实 |
| 其他图 | 常规展示的补充视角：完整清晰、背景简洁，不与其它类型重复 | 不写字 |

一类图只表达一种版式，不能要求模型在一张图里同时产出多种版式。认不出的类型按「其他图 + 不写字」处理，名称原样显示。

一次提交最多 20 张、单类最多 5 张，按「白底图 → 场景图 → 卖点图 → 其他图」的顺序出图。

### 2.2 表单字段如何影响画面

| 用户填写 | 对画面的影响 |
| --- | --- |
| 上传商品图 | 作为真实参考图交给模型；画面要求写明参考图张数与商品一致性硬约束 |
| 商品名称 | 进入商品主体描述，并成为画面可写文字的来源之一 |
| 品牌 | 同上 |
| 投放平台 | 转为平台规格约束；仅当所选比例与画质不低于平台建议时才补规格，否则只写「适配某平台」 |
| 输出语言 | 进入输出规格；不写字的类型以禁字规则为准 |
| 画面比例 / 画质 | 进入画面要求，并决定实际请求的出图尺寸与清晰度 |
| 商品描述 | 卖点图：作为可写文字的「商品事实」；其余类型：作为「画面理解」背景，明确禁止渲染成文字 |
| 自定义配置 | 各类张数展开为一次提交的拆单依据 |
| 模型选择 | 只影响线路，不进入画面要求 |

### 2.3 文字规则

画面文字只能来自用户提供的事实：商品名称、品牌、商品描述。三种情形分别处理：

1. **该类型本来不写字**（白底图 / 场景图 / 其他图）：画面不出现文字、数字、标签、水印或装饰性假文案；商品包装上原有的 logo 与文字保持与参考图一致。
2. **要写字但用户没提供素材**（卖点图）：不出现任何文字，用构图与商品本体表达卖点。
3. **要写字且用户提供了素材**（卖点图）：文字只能取自上述事实，可做不改变含义的压缩或按目标语言等价翻译；来源说明本身不得画进画面。

商品描述每张图只出现一次。所有类型一律禁止模型编造型号、材质、尺寸、参数、功效、认证、销量、价格、优惠或售后承诺。

核对要点：

- 四类图的【任务】【商品一致性】【参考图边界】【输出】【参考图】完全一致，差异只在【本图类型】与是否出现【商品信息｜画面理解】【本图允许文案】的具体写法。

## 3. 商品详情图

### 3.1 一模块一张图

详情图按模块拆分：勾选 N 个模块就产出 N 张图，每张只采用该模块的固定版式。共 16 个模块，一次最多选 10 个；不选时默认取前 6 个。

模块补充要求不是「第二段画面要求」，而是与固定版式合并生效。冲突时的优先级：

1. 商品事实、参考图一致性与可写文字范围是不可覆盖的硬约束。
2. 不冲突时，用户填写的模块补充要求优先于默认版式建议。
3. 默认版式只补充用户未明确覆盖的部分，不带入其它模块的要求。

单模块补充要求最多 1000 字。

### 3.2 表单字段如何影响画面

| 用户填写 | 对画面的影响 |
| --- | --- |
| 上传商品图 | 与主图相同：作为真实参考图，并附参考图张数、参考图边界与商品一致性约束 |
| 商品名称 / 品牌 | 进入商品主体描述与可写文字范围 |
| 商品描述 | 作为「商品事实」；为空时只依据名称与参考图呈现外观，不补参数事实 |
| 模块 | 决定拆几张图、每张采用哪份固定版式 |
| 模块补充要求 | 合并进该模块的画面要求，不跨模块生效 |
| 投放平台 | 转为详情长图的宽度规格；所选画质低于平台建议时不再补规格，与主图口径不同 |
| 输出语言 | 进入文字呈现要求；信息不足时减少信息项，而不是编造 |
| 画面比例 / 画质 | 进入尺寸与交付要求；平台成品宽度只作为生成后缩放或裁切的口径 |
| 模型选择 | 只影响线路，不进入画面要求 |

## 4. 并发生图与配额

并发 = **同一时间交给模型处理的任务数**，与用户点了几次提交无关。一次提交要产出 N 张图，就在服务端拆成 N 个任务：5 张商品主图 = 5 个任务，4 张 = 4 个任务。提交时**不因并发上限拒绝**，超出当前可用名额的任务留在 `queued`，由 worker 分批领取。

### 4.1 提交侧（收单）

- **接口限流**：同一用户 `POST /api/v1/generate` 20 次/60 秒，超出返回 `42901`。按用户计，不按 IP。
- **并发上限随任务快照落库**：准入层把会员套餐的 `maxConcurrent` 写进每个任务参数（`__memberConcurrency`），`0` 表示不限。当前种子里免费档为 `0`（不限），付费档为 10 / 15 / 30 / 50 / 100 / 200。
- **提交不设并发闸门**：N 个任务一次建好，但只有当前有空余名额的部分会被 worker 领取；其余留在 `queued`，等任务结束释放名额后自动继续。
- **父子任务都算任务**：父任务是 `batchIndex = 1` 的第 1 张图，不是纯协调节点；5 张就是 5 个任务。
- **批次原子性**：N 个任务、N 条账单、N 份积分预留在同一事务里完成；余额不足是整批不成立，不会只建出前几张。

### 4.2 调度与执行（发上游）

worker 每轮从 `queued` 中按创建时间先进先出领取，领取前同时检查三项：

| 约束 | 上限来源 | 说明 |
| --- | --- | --- |
| 用户并发 | 任务快照 `__memberConcurrency`（会员套餐） | 该用户当前 `running` 任务数达到上限即跳过；`0` 不限 |
| 渠道并发 | `ModelChannel.concurrencyLimit` | 该渠道当前 `running` 任务数达到上限即跳过；`0` 不限 |
| 进程执行位 | `MODEL_ACTIVE_TASK_LIMIT`（默认 64，范围 1–64） | 本进程同时执行的任务数安全上限 |

被任一约束挡住的任务不会被判失败，仍留在 `queued`，下一轮继续尝试。实际分批示例：

| 场景 | 分批结果 |
| --- | --- |
| 20 张，套餐并发 10，渠道不限 | 10 个 → 10 个，共 2 批 |
| 5 张，套餐并发 10，当前已有 6 个执行中 | 6 + 4 个 → 剩余 1 个下一批 |
| 20 张，套餐并发 10，渠道并发上限 8 | 8 个 → 8 个 → 4 个，共 3 批 |
| 5 张，套餐并发 10，当前已有 6 个执行中，渠道并发上限 8 | 6 + 2 个 → 剩余 3 个下一批 |

其他执行规则：

- **渠道并发槽**：任务派发与轮询回查共用同一组槽位；拿不到槽位时按 200ms 起指数退避等待，最多 `MODEL_SLOT_WAIT_MS`（默认 60 秒）。派发阶段超时按「渠道忙」切线；轮询阶段超时稍后再查。
- **会员快速通道未落地**：`fastChannel` 目前只写入任务参数，没有被 worker 消费；执行侧没有「会员优先、免费让路」的实现。
- **失败边界**：一张图切线或失败只影响自己；只有后台显式终止／整批取消才会中止尚未派发的兄弟任务，并逐张退款。

### 4.3 结果侧（收结果）

- 前端每 1.2 秒拉一次任务列表，只在存在 `queued` / `running` 任务时轮询；任务查询接口没有单独的按用户限流。
- 等待上游结果不占执行位；每次回查上游仍占用渠道并发槽。
- 图像任务轮询间隔 3 秒、总时限 15 分钟；视频 5 秒 / 60 分钟。

### 4.4 已知缺口与边界

- **渠道并发上限按渠道计**：同一模型分组挂在多条渠道时，总容量是各渠道 `concurrencyLimit` 之和，不是整个模型分组的统一上限。
- **用户/渠道计数走数据库**：单实例部署下准确；多实例部署时各进程执行位独立，同一用户的 `running` 计数仍共享数据库，但瞬时判定可能略超上限。
- **免费档并发为 `0`（不限）**：与 `packages-design.md` 中参考站的「免费 2 个并发」口径不一致；收紧会改变全体未订阅用户的行为，需先定产品口径。
- **执行侧没有用户级公平**：全局先进先出，一个用户的大量排队任务可能排在其它用户之后（但不会超过其自身并发上限）。

## 5. 提示词可见性与效果评估

**可见性**：提示词是内部资产。C 端没有预览、查看或复制入口，也没有公开的预览接口，前端不得复刻模板。核对实际提示词使用后台素材详情的「查看提示词」，它按任务参数重建当前模板。

**已知限制**：任务只保存收敛后的参数、不保存最终提示词文本，因此历史任务重建出的是当前模板，不是当时的实发文本。

**效果评估（未实施）**：目前没有 A/B、自动评分或质量回归，版式与模块要求的改动只能人工看样图验证。已具备的只有自动化测试（`main_image.spec.ts` / `detail_image.spec.ts` / `rotate.spec.ts` / `recolor.spec.ts` / `remove_watermark.spec.ts` / `expand.spec.ts` / `enhance.spec.ts` / `matting.spec.ts`）：主图覆盖四类图互斥、未知类型回落、文字范围与禁字、比例 / 画质 / 语言、参考图张数（0 张与 N 张）、拆单后各图要求有差异；详情图覆盖模块合并与拆分、缺失模块键时不回落成详情长图；旋转角度覆盖零变更分支、双模式方向符号、缩放语义与数值格式化、比例不进提示词、商品一致性硬约束与字段白名单；商品换色覆盖三种 HEX 调用约定、换色范围与拼色结构、光影过渡口径、文字 / 品牌硬约束、比例不进提示词与补边裁切例外、输出唯一性与 HEX 白名单；去除水印覆盖三种清除范围互斥与遮罩优先、区域枚举中文映射与脏数据回落、遮罩外像素不变、商品一致性与文字 / 品牌护栏、输出唯一性，以及准入白名单（页面参数通过、误传 `mode=manual` 被拒）；智能扩图覆盖占比注入与脏值回落、位置中文展示名与未知值不吞信息、比例 / 画质不进提示词、补全区域 / 商品一致性 / 文字品牌 / 输出唯一性段落与 `targetImageRatio` 白名单；产品精修覆盖 6 模式互斥、模板码与比例不进提示词、补充要求隔离与优先级、文字 / 品牌硬约束、文本长度与比例白名单；一键抠图覆盖背景色 / 透明度不进提示词、Alpha 透明主体与发丝级边缘、商品一致性与文字品牌硬约束、参考图张数（0 张与 N 张不同）、比例 / 分辨率不进提示词与输出唯一性。

若引入 A/B，至少需要固定输入集，同时记录模型分组、实际线路、参数快照与模板版本，并按「商品一致性 / 版式符合度 / 文字合规 / 可直接上架」四项盲评。

- **无提示词快照**：改模板后无法复现历史实发文本。

- **「描述只作画面理解」不可自动验证**：模型是否确实没有把描述渲染成文字，只能人工抽查。
- **同能力同价**：主图四类、详情各模块共用单价；按版式差异定价需要新增定价维度。

- **旋转角度的正负朝向未与参考站实拍对齐**：`utils.ts` 按参考站相机坐标系把主体模式的方位角取反，提示词只声明正负代表观察方向相反、不代表镜像；左右 / 俯仰的具体朝向仍需实拍确认后才能写进画面要求。

- **商品换色任务参数快照三色并存**：页面只提交 `targetColor` / `customColor` / `ratio` / `size`，`sanitizeParams` 仍给未提交的 `color` 补默认 `#FFFFFF`，`customColor` 在预设档也恒带 `DEFAULT_CUSTOM_COLOR`（`#5546D8`）。后台任务详情的 params JSON 会同时出现三个色值，只有 `targetColor` 生效；清理涉及兼容契约，待裁定后单独处理。

- **去水印的 `ratio` / `size` 静默失效**：专用页 `page.tsx` 仍提交比例与画质，但能力 params 未声明这两个 key，`sanitizeParams` 会丢弃，`model-mapping.ts` 读不到值 → 输出规格走模型默认、后台溯源显示 null。补声明会改变请求意图与画幅语义（编辑类是否允许改画幅未裁定），需产品 / 契约拍板后单独处理，本轮未改。
- **去水印参考站字段无本地实证**：`reference/ijihua/tools-dom.json` 只抓到 `billing-config?toolType=WATERMARK_REMOVAL` 与 DOM，未捕获 `createWatermarkRemoval` 请求体；`detectionMode` 在后端无消费点、`outputFormat` 在默认线路标 `supported:false`，两者仅落参数快照。专用页强制遮罩，`mode=auto` / `region` 两条分支只在通用工具页可达。涉上游语义不自造。
- **去水印版权提示未落到专用页**：`RemoveWatermark.help` 的「请仅处理你拥有版权或已获授权的图片」只在通用工具页 `ToolPageHeader.tsx` 渲染，`ToolShell.tsx` 不渲染；help 中「压在商品主体上的水印建议走云端通道」在当前能力定义里也没有对应实现。授权确认属产品层，本轮只补了「商品本体商标 / 合规标签不得一并清除」的画面护栏。
- **智能扩图的 placement 仅为任务参数快照**：页面按 `occupy + position + 源图尺寸` 算出 `placementX/Y/Width/Height` 并下发，`sanitizeParams` 也会保留，但 `buildPrompt` 与模型请求都不消费；构图只由提示词里的「占比 + 中文位置」定性表达，右侧预览盒与模型产出不保证像素级一致。要按几何精确落点，需先裁定：提示词描述几何 / 引入像素级合成 / 明确接受现状；不得在提示词里自造坐标语义。
- **智能扩图 `occupy=100` 无延展区域**：快捷档含 100%，`expandGeometry.ts` 下 `share=1` 时没有可补全的边缘，但提示词仍要求补全背景、仍按 5 积分计费；`verify-tool-contracts.ts` 已固化「占比 100 通过」，改计费或校验属产品决策，本轮未改。
- **产品精修 6 个模式的细粒度语义未与产品拍板**：`enhance.ts` 的 6 条动作句只复述参考站 pill 的中文名，并用中性措辞收敛（色彩校正写「整体色彩观感与明暗归一」而不写死白平衡 / 色偏口径，材质强化不裁定是否允许改变材质观感）。参考站抓取只覆盖 DOM 与 `billing-config?toolType=PRODUCT_REFINEMENT`，未捕获模板展开后的真实提示词；细粒度口径需产品 / 实拍确认后调整，本轮未自造。
- **产品精修 `imageRatio` 与 `ratio` 仍是两个字段**：专用页同时下发且值相同，`imageRatio` 已补 `^[0-9]+:[0-9]+$` 白名单、不再进提示词；别名归一到单一字段涉及参考站兼容契约，需偏差清单后单独处理，本轮未改。
- **编辑类能力未统一使用 `refCount`**：产品精修只按 `refCount > 0` 声明「以输入图为底图」，未写「参考上传的 N 张图」；recolor / rotate / expand 同型（matting 已按 §12 补齐）。`prompt-engineering.md` §2 要求显式声明参考图张数，跨能力统一口径需单独裁定，本轮未改。
- **一键抠图任务参数快照双色并存**：页面只提交 `selectedColor` / `customColor` / `customAlpha` / `ratio` / `resolution`，`sanitizeParams` 仍给未提交的 `bgColor` 补默认 `transparent`。后台任务详情的 params JSON 会同时出现 `selectedColor:white` 与 `bgColor:transparent`；两者都不再进入提示词，因此只影响溯源展示、不影响出图。清理涉及旧调用方兼容契约，需偏差清单后单独处理，本轮未改。

## 7. 旋转角度（/rotate-angle）

一次提交只上传 1 张商品图、产出 1 张图，按能力单价 5 积分计费。用户表达的是三根滑杆（旋转 −90..90、倾斜 −30..60、缩放 0.8..1.2）、两个模式页签，以及画面比例与画质。

| 用户操作 | 进入提示词 | 进入协议字段 |
| --- | --- | --- |
| 旋转 / 倾斜 | 方位角、俯仰角（以输入图正视角为 0° 基准） | — |
| 缩放 | 商品在画面中放大 / 缩小约百分之几（预览 `scale(zoom)` 的语义） | — |
| 画面比例 | 不写 | `ratio` → 意图 `size` → `aspectRatio` |
| 画质 | 不写 | `size` → 意图 `imageResolution` |
| 模式页签 | 主体模式把方位角取反后提交 `azimuthDeg`，摄像头模式原值提交 | — |

三条硬规则：

- **提示词不重复协议参数**：比例 / 画质由请求字段下发，写进提示词是元指令，可能被模型当成画面内容。`imageRatio` 仅为对齐参考站字段而保留，并带数字比例白名单。
- **三轴全为默认值（0° / 0° / 1）时不重建**：提示词改为保持原视角、占比与场景，避免花 5 积分换一张有轻微形变的重绘图；比例变化仍由协议字段生效。
- **商品一致性与视角重建同时成立**：从新观察角度呈现同一件商品，背景延续原场景与光调、阴影随视角调整，不写「背景保持不变」（改视角 / 改画幅时做不到）；参考图未覆盖的角度只做结构一致的合理推演，不编造背面文字、图案或配件，成图不出现错字、乱码、重复主体、拼接痕迹或装饰性假文案。

后台「查看提示词」用同一 `buildPrompt` 按任务参数重建，与实发文本同源；历史任务仍受 §5「无提示词快照」限制。

## 8. 商品换色（/product-recolor）

一次提交只上传 1 张商品图、产出 1 张换色图，按能力单价 5 积分计费。用户表达的是色板（白色默认 / 浅蓝 / 蓝色 / 红色 / 深红）或自定义 HEX，以及画面比例与画质。

| 用户操作 | 进入提示词 | 进入协议字段 |
| --- | --- | --- |
| 色板预设 / 自定义 HEX | 目标色 `targetColor`，是整段提示词里唯一的变量 | — |
| 画面比例 | 不写；只声明改画幅时最小补边 / 裁切、不拉伸 | `ratio` → 意图 `size` → `aspectRatio` |
| 画质 | 不写 | `size` → 意图 `imageResolution` |

四条硬规则：

- **换色范围锁定主色区域**：保留原有色块分区、拼色结构、印花、缝线、渐变与装饰细节，不把整件商品平涂成单一颜色；金属件、透明件、logo、装饰件与背景保留原色。提示词不再假设「图中唯一的商品」，改为只约束商品数量与结构不变。
- **光影只锁位置与明暗关系**：高光 / 反光 / 阴影的色相随新颜色自然过渡，保留褶皱与曲面上的明暗梯度，不留原色边缘、色斑或光晕。旧文案「反光/高光、阴影…全部不变」在换成白色时会残留彩色边缘，已废弃。
- **文字 / 品牌硬约束复用主图与 SKU**：图中已有文字、logo、价格、参数和标签不重写、不翻译、不美化、不遮挡；不新增价格、优惠、销量、认证、功效、参数、品牌标识或行动号召；成图不得出现错字、乱码、重复主体、拼接痕迹或装饰性假文案。
- **画幅与输出**：不再写「画面尺寸全部不变」——比例与画质由协议字段下发，声明不可变会与后台「查看提示词」显示的比例自相矛盾。改画幅时只做最小范围补边或裁切、外扩区域延续原背景风格、不拉伸商品和背景；只输出一张换色成图，不输出拼图、多色卡、前后对照图或多版本合集。

参数安全：`targetColor` / `customColor` 均带 `^#[0-9a-fA-F]{6}$` 白名单，`validateCapabilityParams` 在扣费前校验，并有换色专属跨字段约束阻止把 `custom` 字面量当颜色；`verify-tool-contracts.ts` 固化参数级断言，`recolor.spec.ts` 固化文案语义断言。

后台「查看提示词」用同一 `buildPrompt` 按任务参数重建，与实发文本同源；历史任务仍受 §5「无提示词快照」限制。未裁定项见 §6（默认白色重绘、任务参数快照三色并存）。

## 9. 去除水印（/watermark-remove）

一次提交只上传 1 张图、产出 1 张去水印成图，当前限时免费（0 积分）。用户表达的是画布上的框选 / 圈选 / 涂抹：提交时才生成透明 PNG 遮罩并上传为素材 id，页面强制要求遮罩，未标注直接本地拦截。

| 用户操作 / 参数 | 进入提示词 | 进入协议字段 |
| --- | --- | --- |
| 画布标注（遮罩 PNG） | 清除范围写「遮罩圈定的水印区域」，并明确范围外像素不变 | `maskAssetId` → 意图 `inputs.mask=1`，只选支持遮罩重绘的线路 |
| `detectionMode=MANUAL` | 不写，手动语义已由遮罩表达 | 参数快照，仅按契约留存 |
| `outputFormat=PNG` | 不写 | 参数快照，默认线路标 `supported:false` |
| 处理方式 `mode`（通用工具页） | `auto` → 自动识别出的水印区域；`region` → 区域中文描述（右下角等），未知值回落「指定区域」 | — |
| 画面比例 / 画质 | 不写 | 见 §6 已知缺口（当前静默失效） |

四条硬规则：

- **遮罩优先**：有 `maskAssetId` 时只描述遮罩范围，不拿 `mode` / `region` 的位置文字冒充圈选；`sanitizeParams` 补出的默认 `mode=auto` 不会改变这条分支。区域枚举 value 先译成中文，未知值与非字符串回落「指定区域」，不把外部文本带进画面要求。
- **区域边界与商品一致性**：范围外的像素、构图、背景与光线保持不变，不做整图重绘；商品结构、颜色、材质、纹理、logo、包装与可见配件与输入图一致，不替换、不变形、不增删物体。措辞复用 `local_redraw.ts` / `matting.ts` / `main_image.ts`。
- **文字 / 品牌护栏**：已有文字、logo、价格、参数与标签保持原样；商品本体上的商标、品牌标识与合规标签不属于水印，不得一并清除；不新增价格、优惠、认证、功效或品牌标识，不复制他人水印与二维码，成图不得出现错字、乱码、重复主体或装饰性假文案。措辞复用 `sku_image.ts` / `recolor.ts`。授权边界属产品层，不写进画面要求。
- **输出唯一**：只输出一张与输入图同一画面的成图，不输出拼图、前后对照图或多版本合集；比例 / 画质不写进提示词。

准入契约：能力 `mode` 只声明 `auto` / `region`，专用页**不提交 `mode`**（`page.tsx` 曾误传 `manual`，会被 `validateCapabilityParams` 在扣费前判 40001）。`remove_watermark.spec.ts` 固化了页面参数通过准入、误传 `manual` 被拒；前端 `product-parameters.spec.ts` 断言 `/generate` 的 payload 不含 `mode`（该用例 mock 了生成接口，只能靠 payload 守契约）。

后台「查看提示词」用同一 `buildPrompt` 按任务参数重建，与实发文本同源；历史任务仍受 §5「无提示词快照」限制。未裁定项见 §6（比例 / 画质静默失效、参考站字段语义、版权提示与「云端通道」）。

## 10. 智能扩图（/image-expand）

一次提交只上传 1 张商品图、产出 1 张扩图成图，按能力单价 5 积分计费。用户表达的是原图占比（快捷 100 / 80 / 60 / 50，默认 80，自定义 1–99）、九宫格原图位置、画面比例与画质。

| 用户操作 / 参数 | 进入提示词 | 进入协议字段 |
| --- | --- | --- |
| 原图占比 `occupy` | 原图占比约 N%（按原图边长口径的定性表达），脏值回落 80 | — |
| 原图位置 `position` | 中文展示名（左上 / 中 / 右下 …），未知值原样保留 | — |
| 画面比例 `ratio` | 不写 | `ratio` → 意图 `size` → `aspectRatio` |
| 画质 `size` | 不写 | `size` → 意图 `imageResolution` |
| `targetImageRatio` | 不写，仅参考站字段快照 | — |
| `placementX/Y/Width/Height` | 不写，仅任务参数快照（见 §6 已知缺口） | — |

四条硬规则：

- **枚举键转展示名**：位置枚举的稳定英文键（`top-left` / `center`）经 `optionLabel` 转成页面展示名再进提示词；把键直接拼进中文句子会被模型当成无关 token，约束形同虚设。未知值原样返回，不静默吞信息。
- **不重复协议参数**：比例 / 画质由请求字段下发，写进提示词是元指令（同 §7）。`original` 是能力侧「保持原图比例」语义，不进意图；旧模板每次默认提交都发「目标画幅 original」，已删除。`targetImageRatio` 带 `^[0-9]+:[0-9]+$` 白名单，与 `rotate.imageRatio` 同口径，拦住经 hidden 字段注入的自由文本。
- **补全范围与商品一致性**：原图按原比例整体放进更大画布，只在新扩出的边缘区域补全背景，不拉伸、不裁切、不改动原图已有像素；补全区域延续原图背景类型、色调、光线方向、阴影、透视与景深，不得出现拼接缝隙、色差、亮度断层或边界光晕，不得扩展成无关新场景；保持同一件商品及其数量、结构、材质、logo、包装、视角与遮挡关系，不得在补全区域复制或新增第二个商品主体、人物、道具或无关物体。措辞复用 `recolor.ts` / `rotate.ts`。
- **文字 / 品牌护栏与输出唯一**：已有文字、logo、价格、参数和标签不重写、不翻译、不美化、不遮挡；补全区域不新增文字、数字、logo、价格标签、水印、二维码、平台界面或他人品牌元素，不新增价格、优惠、销量、认证、功效、参数或行动号召；成图不出现错字、乱码、重复主体、拼接痕迹或装饰性假文案；只输出一张完整扩图成图，不输出拼图、前后对照图或多版本合集。不写「画面尺寸全部不变」——改画幅时那是做不到的。

回归：`expand.spec.ts` 覆盖占比注入与脏值回落、位置中文标签与未知值不吞信息、比例 / 画质不进提示词、构图 / 商品一致性 / 文字品牌 / 输出唯一性段落、`targetImageRatio` 白名单，以及 placement 快照不改变提示词（若后续裁定按几何精确落点，该断言需同步更新）。`verify-tool-contracts.ts` 固化参数级断言：默认 80% 居中、范围 1..100、精确定位字段 hidden、占比 100 通过。

后台「查看提示词」用同一 `buildPrompt` 按任务参数重建，与实发文本同源；历史任务仍受 §5「无提示词快照」限制。未裁定项见 §6（placement 仅元数据、occupy=100）。

## 11. 产品精修（/product-retouch）

一次提交只上传 1 张商品图、产出 1 张精修成图，按能力单价 5 积分计费。用户表达的是 6 个精修模式（综合精修 / 质感增强 / 瑕疵修复 / 色彩校正 / 提升清晰度 / 材质强化）、200 字以内的补充要求，以及画面比例与画质。

| 用户操作 / 参数 | 进入提示词 | 进入协议字段 |
| --- | --- | --- |
| 精修模式 `mode` | 中文模式名 + 该模式专属的动作句与一致性边界 | — |
| `templateCode`（参考站模板码） | 不写，仅任务参数快照 / 溯源元数据 | — |
| 补充要求 `note` / `additionalRequirement` | 独立「补充要求」区块，显式声明冲突优先级，不渲染成文字 | — |
| 画面比例 `ratio` / `imageRatio` | 不写；只声明改画幅时最小补边 / 裁切、不拉伸 | `ratio` → 意图 `size` → `aspectRatio` |
| 画质 `size` | 不写 | `size` → 意图 `imageResolution` |

四条硬规则：

- **模式必须互斥**：上游 `createTemplateImageTool('PRODUCT_REFINEMENT')` 的 `templateCode` 是服务端模板 ID（见 `reference/ijihua/index.js` 的 `Lg` 映射），本地没有模板系统。旧实现把模板码当自然语言写进一句通用提示词，6 个模式除代号外逐字相同 —— 等于选了模板却没实现模板内容。现按 `mode` 生成 6 条差异化动作句，模板码只留在参数快照里；`buildPrompt` 不读 `templateCode`，传错模板码也不会「选 A 得到 B」，未知 mode 回落综合精修。
- **一致性边界随模式收敛**：不再对所有模式一律写「保持结构与颜色真实」——那会与色彩校正、材质强化互相矛盾。`color` 允许整体色彩观感与明暗归一但固有色与配色分区不变，`material` 允许调整材质表面光泽但材质种类与纹理走向不变，其余模式锁死材质、纹理与固有色。
- **补充要求是事实块，不是结构性指令**：用户输入放进独立的 `<<<…>>>` 区块，声明「不得渲染成文字」「与一致性约束冲突时以约束为准」「不得据此替换商品、重绘背景或新增画面元素」；`note` 与 `additionalRequirement` 同源（后者优先），两者均限 200 字，与页面 `NOTE_MAX_LENGTH` 一致。`imageRatio` 带 `^[0-9]+:[0-9]+$` 白名单，比例 / 画质只走协议字段（同 §7 / §8 / §10）。
- **文字 / 品牌护栏与输出唯一**：复用 `recolor.ts` / `sku_image.ts` 同款措辞；只输出一张与输入图同一商品、同一画面的精修成图，不输出拼图、前后对照图或多版本合集。

回归：`enhance.spec.ts` 覆盖 6 模式互斥、模板码与比例不进提示词、补充要求隔离与优先级、文字 / 品牌硬约束、输出唯一性、未知 mode 回落、文本长度与比例白名单。`verify-tool-contracts.ts` 固化参数级断言（模板码与参考站补充要求字段 hidden、旧调用方只传 `mode` 不注入 `templateCode`）。

后台「查看提示词」用同一 `buildPrompt` 按任务参数重建，与实发文本同源；历史任务仍受 §5「无提示词快照」限制。未裁定项见 §6（模式细粒度语义、`imageRatio` 别名归一、`refCount` 统一口径）。

## 12. 一键抠图（/background-remove）

一次提交只上传 1 张商品图、产出 1 张透明底主体图，能力单价 0（页面标注「限时免费」）。用户表达的是背景色板（透明底默认 / 白色 / 浅蓝 / 蓝色 / 红色 / 深红 / 自定义 HEX + 不透明度）与画面比例；结果区的擦除、修补、平移缩放与背景合成都在浏览器本地完成，不是新的 AI 调用。

| 用户操作 / 参数 | 进入提示词 | 进入协议字段 / 前端 |
| --- | --- | --- |
| 背景色板 `selectedColor` / 自定义 HEX `customColor` / 不透明度 `customAlpha` | **不写** | 落库供溯源；`MattingResultEditor` 在 canvas 先 `fillRect` 合成底色，再叠透明主体 |
| 画面比例 `ratio` | 不写 | `ratio` → 意图 `size` → `aspectRatio` |
| 输出分辨率 `resolution` | 不写 | `resolution` → 意图 `imageResolution` |
| 参考图张数 | `refCount` 写成「共参考上传的 N 张商品图」 | — |

四条硬规则：

- **模型只出透明主体**：提示词要求带 Alpha 通道的透明背景图、主体外完全透明、不绘制任何背景 / 底色 / 投影 / 场景；背景色与不透明度全部由前端合成，不进提示词。旧文案把 `selectedColor` 的 token 名（`white` / `light-blue`）当色值、把前端 canvas 的 `customAlpha` 写成「透明度 72%」发给模型，模型既拿不到色值，又可能输出不透明底图，使前端 `fillRect` 的背景色被结果图整体覆盖，已废弃。换任一底色，实发提示词逐字不变。
- **边缘与商品一致性**：发丝级边缘与半透明区域按原图透明度过渡，不留白边、黑边、锯齿、光晕或原背景残影，主体完整不裁切；商品结构、颜色、材质、纹理、logo、包装、数量、视角与遮挡关系全部与输入图一致，不得重绘或替换商品。措辞复用 `main_image.ts` / `sku_image.ts` / `recolor.ts` 的硬约束，不自造一套口径。
- **文字 / 品牌与参考图边界**：图中已有文字、logo、价格、参数与标签保持原样，不新增价格、优惠、销量、认证、功效、参数、品牌标识或行动号召，成图不得出现错字、乱码、重复主体、拼接痕迹或装饰性假文案；参考图只作主体外观与轮廓依据，不复制其背景、桌面、人物、构图与水印。
- **输出唯一**：只输出一张透明底主体图，不输出白底图、带色底图、拼图、前后对照图或多版本合集，不重新创作相似风格的新图，不把抠图结果放进任何新场景。

参数安全：`selectedColor` 为 enum（`MATTING_COLOR_OPTIONS`）、`customColor` 带 `^#[0-9a-fA-F]{6}$`、`customAlpha` 限 0–100，`validateCapabilityParams` 在扣费前校验。颜色参数已完全不进提示词，历史脏数据或未知枚举都无法污染后台重建的提示词（未知 token 在提交侧仍被拒）。

回归：`matting.spec.ts` 覆盖 8 例（七种色板取值 / 旧 `bgColor` / 空参数下实发提示词恒定、无元指令、Alpha 透明与边缘、商品一致性、文字品牌、参考图张数 0/1/3、输出唯一、比例 / 分辨率不进提示词）；`verify-tool-contracts.ts` 固化 5 条语义断言。

后台「查看提示词」用同一 `buildPrompt` 按任务参数重建，与实发文本同源；历史任务仍受 §5「无提示词快照」限制。未裁定项见 §6（任务参数快照双色并存）。
