# 商品主图生图技术规范（`/product-kit`）

状态：已实现。

本文描述 `/product-kit` 商品主图从表单提交到多张主图产出、计费、退款与结果聚合的技术契约。提示词通用规则见 [`prompt-engineering.md`](prompt-engineering.md)，模型选路与失败语义见 [`model-architecture.md`](model-architecture.md)。代码与本文冲突时以代码为准，并在同一次变更中修正本文。

## 1. 范围与核心语义

`/product-kit` 使用能力 `main_image`。一次提交不是生成一张主图，而是按「自定义配置」的变体计数**拆成 N 个独立任务，每个任务产出一张主图**。

核心语义：

- N 等于四类变体计数展开后的数量，范围为 1–20。
- 每张图独立计费、独立生成、独立结算或退款，共享 `batchId`。
- 四类变体各有互斥的画面目标；**不得用一条提示词要求模型同时产出多种版式**。
- 只交付真实模型产出。无可用线路、上游失败或产出不合规时不得回落本地占位图或伪结果。

## 3. 输入契约

### 3.1 页面输入限制

| 字段 | 规则 |
| --- | --- |
| 商品图 | 至少 1 张；页面最多 5 张；单张最大 10MB |
| 商品名称 | 必填，最多 100 字符 |
| 品牌 | 选填，最多 100 字符 |
| 商品描述 | 必填，最多 5000 字符 |
| 投放平台 | 9 项，默认 `taobao`；切换平台带出建议比例与画质，用户手改后不再覆盖 |
| 输出语言 | 10 项，默认 `zh-CN` |
| 画面比例 | 8 项，默认 `1:1` |
| 画质 | `1k` / `2k` / `4k`，默认 `1k` |
| 自定义配置 | 白底图 / 场景图 / 卖点图 / 其他图，每类 0–5，默认 1 / 1 / 1 / 0 |
| 张数上限 | 单次四类合计最多 20 张 |

输入图片的实际上限取 `min(5, 所选模型能力合同的图片输入上限)`。超限时在建单前明确拦住并保留全部素材，不静默丢图。后端通用准入允许更多输入素材，最终仍叠加所选模型的输入数量限制。

### 3.2 变体定义

变体键与 `param-options.ts` 的 `MAIN_IMAGE_VARIANTS` 一一对应；画面要求、文字策略与中文标签同源定义在 `main_image.ts`。

| 变体 | 画面目标 | 文字策略 |
| --- | --- | --- |
| `white_background` 白底图 | 纯白无缝背景（RGB 255/255/255），无投影、无渐变、无场景道具；商品居中完整呈现，正面或微侧 45°，柔和均匀主光加底部浅反射 | 禁字 |
| `scene` 场景图 | 商品置于与品类相符的真实消费场景；道具克制不遮挡，光线与阴影自然，商品为唯一视觉主体，背景适度虚化 | 禁字 |
| `selling_point` 卖点图 | 一图讲清一个卖点；商品主体占画面 45%–60%，其余区域用简短文字与图标标注 1–3 个卖点 | 允许写字，但限定在事实闭集内 |
| `other` 其他图 | 常规展示的补充视角：商品完整清晰、背景简洁、构图干净，不与其它变体重复 | 禁字 |

规则：

- 所有变体都必须遵守商品一致性：结构、颜色、材质、纹理、logo、包装与可见配件与参考图一致，不替换、不拉伸、不增删部件。
- 参考图只作为商品外观依据，不是版式、场景或文案参考；不得复制参考图背景、桌面、人物、构图、文字与水印。
- 认不出的变体键回落到 `other` 的画面要求，**文字策略按「不允许写字」处理**（更安全的一侧），标签原样显示不吞信息。

## 4. 字段如何进入生成

| 输入 | 进入方式 |
| --- | --- |
| 商品图 | 作为真实参考图经 `inputAssetIds` 传给模型，不转写成一句文字提示词；提示词写明参考图张数与商品一致性硬约束 |
| 商品名称 | 进入商品主体描述（`商品「名称」`），并作为文案闭集来源 |
| 品牌 | 进入商品主体描述（`品牌 X`），并作为文案闭集来源 |
| 投放平台 | 转为平台规格约束；仅当所选比例与画质不低于平台建议时才补规格（如「适配淘宝平台（主图常规 1:1、边长 ≥800px）」，否则只写「适配淘宝平台」） |
| 输出语言 | 进入输出规格句（`画面内文字使用 <语言> `）；禁字变体以禁字规则为准 |
| 画面比例 | 进入提示词，同时参与生成请求的尺寸意图 |
| 画质 | 进入提示词（`输出规格 1K/2K/4K`） |
| 商品描述 | 卖点图：进入文案闭集；白底图、场景图、其他图：作为「画面理解」上下文，显式禁止渲染成画面文字 |
| 自定义配置 | 计数展开为 `variants` 参数，由服务端 `outputPlan` 拆成 N 个任务 |
| 模型选择 | 仅用于解析 `modelKey` 与线路，不直接进入提示词 |
| 参考图张数 | 由 `buildPrompt` 第二个参数 `refCount` 显式传入并在提示词中说明 |

提示词按固定顺序组织：`【任务】` → `【本图类型】` → 可选 `【商品信息｜画面理解】` → `【商品一致性｜硬约束】` → `【参考图边界｜硬约束】` → `【本图允许文案】` → `【输出】` → 可选 `【参考图】`。每个区块只表达一类指令，不得出现「上一段禁字、下一段允许写字」的自相矛盾。

## 5. 文案闭集与禁字

允许写入画面的文案闭集只由用户填写的事实构成：

```text
商品名称「<productName>」
品牌「<brand>」
商品事实：<description>
```

三种情形分别处理，避免指令冲突：

1. **该变体本来就不写字**（白底图 / 场景图 / 其他图）：明确禁字，不得出现文字、数字、标签、logo 文字、水印或装饰性假文案；商品本体上原有的 logo 与包装文字保持与参考图一致即可。
2. **该变体要写字但用户没提供素材**：画面不出现任何文字，用构图与商品本体表达卖点。
3. **该变体要写字且用户提供了素材**：文字只能取自上述闭集；来源标签只是标签，不得原样画进画面；只允许不改变含义的压缩或按目标语言等价翻译。

商品描述的特殊处理：

- **卖点图**：描述进入文案闭集（`商品事实`），只注入一次。
- **白底图、场景图、其他图**：描述放入独立的 `【商品信息｜画面理解】` 区块，用于理解商品属性、适用场景、构图与卖点表达，并显式声明「不在画面中生成文字」；因为该变体已禁字，不会与文案规则冲突。
- 同一段描述在一次提示词里只出现一次，不允许既进闭集又进理解区块。

所有变体一律禁止模型编造型号、材质、尺寸、参数、功效、认证、销量、价格、优惠或售后承诺。

## 6. 输出计划与批次

`parseMainImageVariants()` 解析逗号分隔的 `variants`：

- 过滤未知变体。
- 按 `MAIN_IMAGE_VARIANTS` 声明顺序展开：一类填 3 就出现 3 次。
- 截断到 20 张（`MAIN_IMAGE_MAX_OUTPUTS`）。

`outputPlan()` 为每张生成一个输出计划：

```ts
{
  key: 'scene-2',
  label: '场景图',
  params: { variant: 'scene', variantLabel: '场景图' }
}
```

准入行为：

- 输出计划为空时回落为单个任务（直接使用原参数）；页面在张数为 0 时不允许提交。
- N > 1 时写入 `batchId` / `batchIndex` / `batchSize`；第一个任务作为父任务，其余任务的 `parentTaskId` 指向它。
- N 个任务各建一条账单、各预留一份积分，共享线路与价格快照；建任务、建账单、预留积分在同一事务内完成。
- 会员并发按任务数计：`maxConcurrent` 随任务参数落库，worker 领取时要求「该用户当前 `running` 任务数 < 上限」；N 张超出名额的部分留在 `queued` 分批执行，不在提交阶段拒绝。父任务本身也产出一张图，不是纯协调节点。
- 响应返回父任务 id 与合计 `creditCost`；N > 1 时附带 `batchId` / `batchSize`。

计费口径：

- 单价由 `CreditPriceService.resolve()` 在运行期解析（后台覆盖价、限时免费优先），任务快照与账单同源。
- 页面的价签按本次张数计算，与实际建单数量同源（都走 `buildVariantPlan`）；前端不自行推算最终金额。

## 7. 提交与幂等

提交只有一条网络请求：

```http
POST /api/v1/generate
Idempotency-Key: gen-...
```

请求参数包含 `capability=main_image`、`modelKey`、`inputAssetIds`，以及 `productName / brand / platform / language / description / ratio / size / variants`。

提交前依次完成：

1. `resolveModel('main_image')` 解析真实模型，并按模型能力合同复查图片数量上限。
2. `ensureProject()` 确保任务落入有效项目。
3. `ensureAssetsInProject()` 把跨项目素材复制到当前项目；复制失败停在建单之前，绝不以跨项目 asset id 提交。
4. 按输入指纹生成幂等键；网络失败后重试复用同一键，服务端返回既有任务，不重复扣费。

请求一旦发出，服务端就可能已经建单扣费。响应丢失时页面重拉结果并提示「可能已提交」，不得让用户误以为未提交而重复操作。

## 8. 结果展示、删除与重新生成

- 结果列表按 `batchId` 聚合成「一次生成」，批内按 `batchIndex` 升序；标签优先取任务的 `variantLabel`。
- 轮询间隔 1.2 秒，仅在存在 `queued` / `running` 任务时轮询；失败任务也进列表，让用户看到具体是哪一类主图失败。
- 批次状态：任一生成中 → 生成中；成功与失败并存 → 部分失败；全部失败 → 生成失败；其余 → 已完成。
- 删除一次生成时只删除 `batchIndex=1` 的父任务，服务端连带删除子任务、产出素材与磁盘文件；批内仍有生成中任务时删除入口禁用。
- **重新生成只回填、不直接建任务**：从批次首个任务还原表单字段，按整批任务的 `variant` 统计还原各类张数，原图不可用时保留文字参数并提示重新上传；用户确认后再次提交。

## 9. 提示词可见性

- 提示词是内部资产。**C 端不提供任何提示词预览、查看或复制入口**，也不存在公开的提示词预览接口；前端不得复刻提示词模板。
- 需要核对实际提示词时使用后台素材详情的「查看提示词」：`describeGeneration()` 用任务快照参数调用同一份 `buildPrompt` 重建，与提交时发给模型的文本同源。
- 任务不保存最终提示词文本，因此提示词定义变更后，历史任务重建出的文本是**当前模板**，不是当时的实发文本。该限制与通用提示词规范一致，见 [`prompt-engineering.md`](prompt-engineering.md) §7 与 §10。

## 11. 已知缺口

- **无提示词快照**：任务只存收敛后的参数，后台重建提示词使用当前能力定义；改模板后无法复现历史实发文本。
- **无提示词效果评估**：没有 A/B、评分或质量回归，变体 brief 改动只能人工看样图。
- **描述作为「画面理解」不可自动验证**：模型是否确实没有把描述渲染成文字，只能人工抽查产出。
- **四类变体同价**：售价在能力级，白底图 / 场景图 / 卖点图 / 其他图共用一份单价；若要按变体差异定价，需要新增定价维度。
- **张数上限两处维护**：页面单类上限（5）与服务端总量上限（20）分别声明，改动时必须同步。

## 12. 变更检查清单

修改商品主图生成链路时至少检查：

- [ ] 变体键、标签、brief、文字策略与页面 `VARIANT_FIELDS` / `VARIANT_LABELS` 同步。
- [ ] 变体 brief 仍互斥，spec 覆盖「不要求同时生成其它类型」。
- [ ] 非卖点图仍把描述放入画面理解区块并显式禁字；卖点图描述只进文案闭集一次。
- [ ] 未知变体回落安全默认，不崩、不吞信息。
- [ ] `outputPlan` 顺序稳定、上限 20，服务端与页面张数口径一致。
- [ ] 每张仍各建一条账单，建任务 / 建账单 / 预留积分仍在同一事务。
- [ ] C 端未新增提示词预览入口，提示词未下发前端。
- [ ] 平台规格只在比例与画质不低于建议时补入，用户显式选择优先。
- [ ] 页面输入上限与模型能力合同上限的叠加逻辑未被破坏。
