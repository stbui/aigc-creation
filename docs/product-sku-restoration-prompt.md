# 商品 SKU 图页面复原提示词

## 1. 任务目标

复原参考站 `https://ijihua.cn/product-sku` 的商品 SKU 图页面，覆盖页面布局、视觉样式、交互、业务功能与本地适配差异。

目标代码：

- JS：`https://ijihua.cn/assets/index-Do3-_JpH.js`
- CSS：`https://ijihua.cn/assets/index-lrpwPXNE.css`

本地目标文件：

- 页面：`frontend/src/pages/ProductSkuPage.tsx`
- 区域框选：`frontend/src/components/SkuRegionEditorModal.tsx`
- 结果面板：`frontend/src/components/SkuResultPanel.tsx`
- 历史面板：`frontend/src/components/SkuHistoryPane.tsx`
- 页面骨架：`frontend/src/components/ToolShell.tsx`
- 样式：`frontend/src/styles/global.css`
- 能力定义：`backend/src/capabilities/definitions/sku_image.ts`

## 2. 必须遵守的边界

1. 复用现有鉴权、项目、上传、素材库、手机上传、能力运行时检测和真实生成接口。
2. 不得用前端拼图、固定图片、假数据或本地模拟结果冒充 AI 生成。
3. 后端暂无参考站批处理接口时，可以一次提交后循环创建多个 `sku_image` 任务，但必须保持“一次提交、一组结果、一个下载入口”的产品语义。
4. 不修改与本任务无关的页面；不回滚工作区已有 WIP；不提交 Git。
5. 所有新增文案使用中文，错误必须区分“未配置模型通道”“参数不合法”“生成失败”。

## 3. 当前实现与参考站差异

| 模块 | 本地现状 | 参考站目标 |
| --- | --- | --- |
| 页面结构 | 输入 + 结果两栏，整页滚动 | 输入 432px / 结果自适应 / 历史 192px 三栏，仅输入栏滚动 |
| 模板上传 | 上传后直接出现简易框选 | 上传后自动打开独立区域编辑器；模板卡显示缩略图与重编辑入口 |
| 区域编辑 | 模板图内拖拽矩形 | 全屏编辑器，支持抓手、矩形、椭圆、画笔、橡皮、缩放、撤销、重做、清空 |
| 使用步骤 | 始终显示 | 未确认区域时显示；确认后替换为 SKU 清单 |
| SKU 数据 | 名称 + 颜色 | 每个 SKU 含名称；每个变体区域含文字说明 + 可选参考图 |
| 提交方式 | 每个 SKU 单独调用生成接口 | 用户只点一次；一次提交整组 SKU，结果聚合展示 |
| 结果区 | 通用“全部生成图”网格 | 当前批次主图 + 横向 SKU 缩略图 + 一键下载 |
| 历史区 | 无独立历史栏 | 右侧独立历史栏，支持打开、重新编辑、移除、下载、滚动分页 |
| 参数 | 比例、画质 | 比例、画质；提交时同步框选坐标、区域类型和变体说明 |

## 4. 页面布局

### 4.1 桌面端

根容器采用三栏 CSS Grid：

```css
grid-template-columns: minmax(360px, 432px) minmax(0, 1fr) 192px;
gap: 12px;
padding: 16px;
height: calc(100vh - var(--workspace-topbar-height));
background: #f6f7fb;
overflow: hidden;
```

- 左栏：模板图卡、使用步骤 / SKU 清单、高级设置、提交按钮。
- 中栏：当前批次结果，白底、14px 圆角，占满可用高度。
- 右栏：历史记录，白底、14px 圆角，独立滚动。
- 只允许左栏自身滚动；页面、结果栏、历史栏不得出现页面级双滚动条。

### 4.2 平板端

- `901px–1366px`：左栏压缩为 `216px`，中栏占满剩余宽度；历史栏改为贴右侧的 200px 滑出面板，默认收起，通过右侧浮动按钮打开。
- 历史面板打开时主区域宽度不变，不弹遮罩、不挤压画布。
- `901px` 以下：改为单栏，页面高度自动，左栏与结果栏依次排列。

### 4.3 手机端

- `560px` 以下页面内边距为 8px。
- 上传区最小高度约 130px。
- 结果区最小高度 560px。
- 区域编辑器接近全屏，工具栏允许换行或横向滚动，画布高度不超过 `60vh`。
- 所有触控目标不小于 40px，画布使用 `touch-action: none`。

- 标题字号 14px / 行高 20px / 字重 700。

- 四个步骤编号为紫色圆形 24px。
- 步骤之间使用 `#d9ddea` 竖向虚线。
- 标题 14px，说明 12px / 行高 20px。

### 5.4 SKU 清单

- 标题行：“SKU 清单” + “添加 SKU”。
- 最多 10 个 SKU，至少 1 个。
- 每个 SKU 卡片 16px 内边距，卡片间距 12px。

- 每个区域对应一行变体：
  - 行背景 `#fafbfc`，圆角 8px，内边距 12–16px。
  - 标题左侧显示区域编号图标，右侧提供“上传参考图”“素材库”。
  - 文本输入占位：“描述该区域要替换成的商品、颜色、材质等”。
  - 可选参考图为 48×48 缩略图，右上角移除按钮。
  - 文字说明和参考图至少填写一个，否则该行显示红色边框。
- “添加 SKU”超过 10 个后禁用。

### 5.5 提交区

- 使用现有 `ToolSettingsPopover`，显示比例与画质。
- 默认比例 `1:1`，默认画质 `1K`。
- 主按钮文案“立即生成”，全宽，最小高度 38px，紫色。
- 按钮下方或上方显示积分消耗。
- 校验失败时按钮禁用，并给出当前阻断原因。

### 5.6 结果区

- 头部：“SKU 批量结果”，可附本批次数量。
- 有结果时右上角显示“一键下载”。
- 主图区域使用浅灰底、`object-fit: contain`，点击打开大图。
- 下方横向缩略图：56×64px，选中项 2px 紫色边框，底部显示 SKU 名称。
- 生成中显示与主图同尺寸的骨架，不得退回“尚未提交”空态。
- 空态显示标题“商品SKU图”和说明“一张图，批量套出版式完全一致的整组 SKU 图。”

### 5.7 历史栏

- 标题“历史记录”，高度 48px。
- 列表间距 9px，卡片宽度 100%。
- 缩略图正方形，点击打开结果。
- 每项提供“打开”“重新编辑”“下载”和“移除”。
- 每页显示 10 条，滚动到底部再加载下一页。
- 历史为空时文案“暂无历史记录”。
- URL 参数 `submissionId` 存在时，尝试恢复对应任务；无权限或已删除时给出明确提示。

## 6. 区域编辑器

### 6.1 打开时机

- 上传/更换模板图成功后自动打开。
- 点击模板卡的“重新框选”再次打开。
- 编辑器关闭时若未确认，保留上一次已确认区域。

### 6.2 工具

工具栏从左到右：

1. 抓手
2. 矩形
3. 椭圆
4. 画笔
5. 橡皮
6. 画笔大小
7. 撤销
8. 重做
9. 缩放减 / 当前缩放 / 缩放加
10. 清空
11. 确认

“确认”按钮显示已选区域数量，例如“确认 (2)”。

### 6.3 画布行为

- 画布中央显示模板图，保持原始宽高比，最大不超过编辑器可用区域。
- 区域坐标统一保存为 0–1 归一化值。
- 矩形：拖拽创建，拖拽结束后选中。
- 椭圆：拖拽创建，渲染为椭圆。
- 画笔：按指针轨迹记录点集，同时计算包围盒。
- 橡皮：点击区域删除对应区域。
- 抓手：拖动空白区域平移画布；拖动区域移动区域。
- 选中区域显示 4 个缩放手柄；拖拽手柄调整位置和尺寸。
- 区域编号从 1 开始，显示在左上角。
- 最多 3 个区域；达到上限后不再允许新建，并提示“最多框选 3 个变体区域”。
- 支持 `Delete/Backspace` 删除选中区域，`Esc` 关闭编辑器。
- 撤销/重做应覆盖新建、移动、缩放、删除和清空。

### 6.4 区域数据结构

```ts
type SkuRegionType = 'rect' | 'ellipse' | 'brush';

interface SkuRegion {
  id: string;
  type: SkuRegionType;
  x: number;
  y: number;
  width: number;
  height: number;
  points?: Array<{ x: number; y: number }>;
}
```

提交给后端时至少包含 `regionId/x/y/width/height/type`；画笔的 `points` 可作为本地编辑状态保留，后端仅使用包围盒。

## 7. SKU 数据模型

```ts
interface SkuVariantContent {
  regionId: string;
  instruction: string;
  reference?: {
    id: string;
    url: string;
    name: string;
  };
}

interface SkuItem {
  key: number;
  name: string;
  variants: Record<string, SkuVariantContent>;
}
```

默认创建一个 `SKU 1`。新增 SKU 时自动复制当前区域键，但清空说明与参考图。

## 8. 提交与生成

### 8.1 提交前校验

- 模板图存在。
- 至少 1 个区域。
- 1–10 个 SKU。
- SKU 名称非空、≤15 字符、忽略大小写唯一。
- 每个 SKU 的每个区域至少有一个非空说明或参考图。

### 8.2 请求语义

参考站批处理字段：

```ts
{
  clientRequestId,
  sourceAssetId,
  imageRatio,
  resolution,
  regions: [{ regionId, x, y, width, height }],
  items: [{
    clientItemKey,
    skuName,
    modelGuideAssetId,
    variants: [{
      regionId,
      instruction?,
      referenceAssetId?
    }]
  }]
}
```

本地无批处理接口时，对每个 SKU 创建一次 `sku_image` 任务：

```ts
{
  projectId,
  capability: 'sku_image',
  inputAssetIds: [templateAssetId, ...uniqueReferenceAssetIds],
  params: {
    skuName,
    regions: JSON.stringify(regions),
    variants: JSON.stringify(variantPayload),
    batchId,
    batchIndex,
    batchSize,
    ratio,
    size
  }
}
```

注意：

- 参考图在 `inputAssetIds` 中去重，并在 `variants` 中记录 `referenceAssetId` 与 `referenceIndex`。
- `batchId` 是一次用户提交的稳定标识；同一次提交创建的所有任务必须共用同一个值。
- `batchIndex` 从 1 开始，按 SKU 在清单中的顺序递增；`batchSize` 是本次提交计划生成的总数，即使部分请求失败也保持原值。
- 每个任务使用独立幂等键：首次提交为 `sku-${batchId}-${batchIndex}`，失败重试为 `sku-${batchId}-${batchIndex}-retry-${attempt}`。
- 先并行创建任务，再统一轮询；不得逐张串行等待导致首张出图后按钮仍不可用。
- 任一任务失败不得回滚已成功结果；显示失败数量，并允许一键重试失败项。

### 8.3 生成状态

- 提交后立即进入“生成中”，按 SKU 名称展示占位。
- 轮询结束逐个回填结果。
- 成功的图插入当前批次和历史列表首位。
- 失败项保留失败占位，显示 `taskErrorText(errorCode)`。
- 全部结束后 `notifyCreditsChanged()`。

### 8.4 失败重试与批次收敛

- 只有任务创建失败或轮询得到 `failed` 的 SKU 才进入失败态；已成功的结果不得被回滚。
- 当前批次仍在执行时，重试按钮保持禁用，避免同一 SKU 重复提交。
- 当前批次全部结束后，结果面板提供：
  - “重试失败项 (N)”：一次重试所有失败 SKU；
  - “重试此 SKU”：仅重试当前失败缩略图。
- 重试必须复用当前提交计划中的模板、区域、SKU 名称、说明、参考图和画质，只替换目标序号对应的任务。
- 重试仍使用原 `batchId/batchIndex/batchSize`，成功后回填原缩略图位置，不得新增一条重复历史记录。
- 并发保护使用页面级运行锁（`batchRunningRef`）；重试期间不得再次发起整批提交。
- 若请求在创建任务前失败，服务端不会产生该 SKU 的任务记录；历史批次可用 `已完成数/计划数`（例如 `1/2`）如实展示，不得伪造失败任务或占位图。
- 刷新页面后，失败重试只对当前会话中仍持有提交计划的批次生效；历史恢复只读取真实任务，不补造不存在的 SKU。

## 9. 后端提示词适配

扩展 `backend/src/capabilities/definitions/sku_image.ts`：

- 声明隐藏参数 `variants`，长度上限 6000。
- 解析每个变体的 `regionId/instruction/referenceAssetId/referenceIndex`。
- `buildPrompt` 明确写出：
  - 只修改框选区域；
  - 区域 1/2/3 的具体文字要求；
  - 参考图编号与区域的对应关系；
  - 框外主体、文字、版式和背景保持不变；
  - 输出图与模板图保持同一画幅和视角。
- 不得把未声明的变体字段写入任务参数。

## 10. 历史与恢复

- 历史数据来自真实 `generateApi.list()`，按 `sku_image` 过滤。
- 同一 `batchId` 的任务聚合为一条批次历史，组内按 `batchIndex` 排序；没有 `batchId` 的旧任务各自独立，避免误合并。
- 批次总数为 `max(实际任务数, batchSize)`。全部完成时显示 `N 款`；部分创建失败时显示 `实际数/计划数`。
- 历史项点击“打开”后，中栏展示该批次全部已完成结果，并支持缩略图切换。
- “重新编辑”并行读取整批任务详情，恢复：
  - 模板图；
  - 区域坐标与类型；
  - 每个 SKU 的名称；
  - 每个变体的说明和参考图；
  - 比例、画质。
- 整批恢复时对所有任务的 `inputAssetIds` 去重，再按 `referenceAssetId` 回填各区域参考图。
- 若输入素材已删除，提示“原模板或参考图已不可用”，不要构造假图片。
- 单张结果可直接下载；多张结果使用一个 ZIP 打包下载，文件按 SKU 顺序编号。
- 删除批次历史前二次确认，并并行删除组内全部任务；部分删除失败时报告失败数量，并保留未删除项。
- 历史批次是“一次用户操作、一组结果、一个下载入口”；后端没有批次实体时，仅以任务参数承载批次语义。

## 11. 响应式与无障碍

- 所有按钮有可读 `aria-label` 或明确文案。
- 编辑器对话框使用 `role="dialog"`、`aria-modal="true"`。
- 键盘焦点可见；关闭按钮支持键盘操作。
- 图片有业务化 `alt`。
- `prefers-reduced-motion` 下关闭非必要过渡。
- 不因 192px 历史栏挤压导致主图变形；窄屏直接切成两栏或单栏。

## 12. 验收标准

1. 1440px 宽桌面端呈现 `432 / 自适应 / 192` 三栏，页面无整体滚动。
2. 上传模板图后自动打开区域编辑器。
3. 编辑器可创建矩形、椭圆和画笔区域，支持移动、缩放、删除、撤销、重做、清空。
4. 最多只能确认 3 个区域。
5. 确认区域后使用步骤卡消失，出现 SKU 清单。
6. 可创建最多 10 个 SKU；名称与变体说明校验生效。
7. 每个区域可设置文字说明和参考图，缩略图可移除。
8. 点击“立即生成”只触发一次用户操作，整组 SKU 并行提交。
9. 生成中、部分失败、全部成功三种状态清晰可见。
10. 结果区支持主图预览、SKU 缩略图切换和一键下载。
11. 同一次提交的任务共用 `batchId`，并带有正确的 `batchIndex/batchSize`；历史只出现一条批次记录。
12. 部分失败时可“重试失败项”或“重试此 SKU”，重试成功后回填原位置且不新增重复历史。
13. 右侧历史栏支持打开整批、整批重新编辑、ZIP 下载、整批删除和滚动分页。
14. 部分批次显示 `已完成数/计划数`，不得用假任务补齐。
15. 手机端 390×844 无横向溢出，编辑器与提交区可正常操作。
