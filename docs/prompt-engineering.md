# 生成提示词规范

提示词是**能力定义的一部分**：唯一入口是 `CapabilityPlugin.buildPrompt`，由 `backend/src/capabilities/definitions/<id>.ts` 提供。本文件规定提示词的结构、事实闭集、多图拆分、参数槽位、文本工具、协议边界、版本追溯与测试要求。能力清单与 `outputPlan` 机制见仓库根 `CLAUDE.md`，模型请求链路见 [`model-architecture.md`](model-architecture.md)。

## 1. 单一事实源与链路

```
任务准入（validate + sanitize params）
  → outputPlan 拆成 N 个子任务（每张一套 params）
  → task-request.service 调 def.buildPrompt(params, refCount)
  → 协议执行器把 prompt 映射到上游字段
  → 模型
```

硬约束：

- 提示词只在能力定义里生成；**前端不得复刻模板**。
- **提示词不对 C 端开放查看**：提示词是内部资产，前台页面不提供任何预览 / 查看 / 复制入口，也不存在公开的提示词预览接口；需要核对实发提示词时走后台素材详情（`/admin/assets` 的「查看提示词」，按任务参数用同一份 `buildPrompt` 重建）。
- 当前 18 项能力全部声明 `buildPrompt`；缺失由 `assertCapabilityIntegrity` 在装配期拦下。
- 协议插件只做字段映射，不在执行期改写业务提示词。

## 2. 提示词结构

一条提示词按以下顺序组织，缺项可省略，不得打乱：

| 顺序 | 内容 | 要求 |
| --- | --- | --- |
| 1 | 本次目标 | 明确「本次只生成什么」，多图能力必须写死本张的唯一目标 |
| 2 | 主体与事实 | 只注入用户填写的事实；事实与来源标签分开表述 |
| 3 | 场景 / 构图 / 镜头 / 光线 | 与目标匹配，不同变体之间必须互斥 |
| 4 | 风格与质感 | 电商视觉语义，不堆砌无用形容词 |
| 5 | 约束 | 禁字、禁改结构、禁编事实、参考图角色 |

规则：

- 每次生成只解决一个画面目标；**不要用一条提示词要求模型同时产出多种版式**。
- 事实只能来自用户输入（商品名称、品牌、商品描述）；不得臆造价格、销量、认证、功效、促销承诺。
- 用户输入作为「事实块」引用，不直接混入结构性指令；来源标签（如「商品名称」）明确标注为标签，不得原样画进画面。
- 文字策略显式化：不允许写字的变体明确禁字；允许写字的变体把可用文字限定在事实闭集内。
- **理解上下文与文案素材分开**：不允许写字的变体仍可注入用户填写的商品描述，但必须放在独立的「画面理解」区块并显式声明不得渲染成文字；允许写字的变体已把描述纳入文案闭集，不得重复注入。
- 参考图数量通过 `refCount` 显式传入并在提示词中说明（「参考上传的 N 张图」），不靠往 params 塞隐藏字段。
- 提示词使用中文作为规范语言；协议层不做业务级翻译或改写。

## 3. 参数与变量槽位

- 只有 `CapabilityPlugin.params` 声明过的参数会被 `sanitizeParams` 保留；新增参数必须同时声明，否则会被静默丢弃。
- 服务端代填字段（`batchId` / `batchIndex` / `batchSize` / `variantLabel` 等）必须声明为 `hidden: true`，否则持久化或复用时会丢。
- 不在 params 里注入 `__refCount` 一类内部字段；参考图张数用 `buildPrompt` 第二个参数。
- 枚举值未知时回落到**更安全的一侧**（例如未知变体按「不允许写字」处理），不静默当成默认变体。
- 文本长度上限必须显式声明并在 DTO 校验；当前仅详情图模块提示词限制 1000 字（`MAX_SECTION_PROMPT_LEN`），新增长文本参数必须补上限。
- 数值参数（比例、尺寸、张数、时长）从参数选项集合取值，不在提示词里接受自由文本。

## 4. 多图输出（outputPlan）

声明了 `outputPlan` 的能力，一次提交在准入层拆成 N 个独立任务：每张各扣一份 `creditCost`、各自成败与退款、共享 `batchId`。

当前 3 项能力使用：

| 能力 | 拆分维度 | 约束 |
| --- | --- | --- |
| `main_image` | 勾选的主图变体 | 每张只要求自己的变体，画面要求互斥 |
| `detail_image` | 勾选的详情模块 | 每张一个模块，模块提示词可覆盖默认 |
| `shoppable_carousel` | 生成张数（6–10） | 每张独立文案与版式，不靠一条提示词拼多图 |

规则：

- 每个 `CapabilityOutput` 的 `key` 在批次内稳定、`label` 可直接展示。
- 拆分后的提示词必须**互不相同**，且不得出现「同时生成其他变体」的指令。
- 拆分的条数与顺序由能力定义决定，前端只按批次聚合并按 `batchIndex` 展示，不另做预览。
- 新增多图能力必须同时补：`outputPlan`、每张的互斥 brief、拆分测试、计费说明。

## 5. 文本工具提示词

`prompt-tools` 的润色与图片转提示词走 text 模态，不进任务与账单：

- 润色：只改写措辞与结构，不新增未提及的画面要素，不编造品牌、价格、销量、功效。
- 图片转提示词：只客观描述图中真实存在的内容；图片以 base64 data URL 内联，不依赖上游回拉；只读当前用户自己的素材。
- 输出为一段连贯中文，不分点、不解释、不加引号；`maxTokens` 与 `temperature` 在服务层显式设置。
- 无可用线路或全部失败返回 `50201`，**不拼接模板文案**（见 [`error-copy.md`](error-copy.md)）。

## 6. 协议与适配边界

- 协议执行器接收最终 `prompt` 字符串；厂商字段映射由 `backend/plugins/<plugin>/manifest.json` 声明。
- 适配层不得追加业务级指令（如「请画白底图」）；这类内容属于能力定义。
- 厂商特有的提示词技巧（negative prompt、质量词、风格后缀）应放在能力定义或插件声明的可配置字段中，不写在页面或临时脚本里。
- 执行期不得静默截断提示词；如上游有长度限制，应在能力定义或 manifest 中显式声明并提前处理。
- 上游原始报错不得回写进提示词或用户文案。

## 7. 版本与可追溯

当前提示词在任务请求时实时计算；`GenerationTask.params` 保存收敛后的用户参数，**不保存最终提示词文本**，`ApiCallLog` 也不记录提示词。

因此：

- 修改 `buildPrompt` 属于**行为变更**，必须同批更新该能力的 spec，并在交付说明里写清影响范围。
- 不得在热修里悄悄改提示词；提示词变更与代码变更一起进入评审。
- 历史任务无法还原当时发给模型的完整提示词（已知缺口，见 §10）。

## 8. 测试要求

提示词相关能力的 spec 在 `backend/src/capabilities/definitions/*.spec.ts`，当前 7 个文件。新增或修改提示词至少覆盖：

- [ ] 不同变体 / 模块的提示词互不相同。
- [ ] 每个变体只要求自己的目标，不出现其他变体的要求。
- [ ] 用户事实只注入一次；来源标签不会被要求写进画面。
- [ ] 未知枚举值回落到安全默认，不崩、不吞信息。
- [ ] 文字策略正确：不该写字的变体明确禁字。
- [ ] `refCount` 正确进入提示词（0 张与 N 张不同）。
- [ ] `outputPlan` 的条数、顺序、子参数稳定，前端批次聚合与之一致。
- [ ] 文本工具的指令包含「不编造事实」「不分点」等约束。

## 9. 新增 / 修改能力提示词清单

- [ ] `buildPrompt` 已声明，且只描述本张目标。
- [ ] 事实来自用户输入，闭集外内容不出现。
- [ ] 文字策略显式（允许 / 禁止 / 事实闭集）。
- [ ] 参考图数量使用 `refCount`，不塞进 params。
- [ ] 参数已声明，长文本有上限。
- [ ] 多图能力已声明 `outputPlan`，每张 brief 互斥。
- [ ] spec 覆盖互斥、闭集、回落与批次一致性。
- [ ] 更新能力定义所在文档与 `CLAUDE.md` 的数量描述。

## 10. 已知缺口

- **无提示词版本与快照**：任务与调用记录不保存最终提示词，历史任务无法复现当时的输入。
- **长度上限不统一**：只有详情图模块提示词限制 1000 字，其余模板与文本参数没有统一上限。
- **无效果评估**：没有提示词 A/B、评分或质量回归，改动好坏只能靠人工看样图。
- **中文单语策略**：所有提示词按中文编写，没有按模型 / 地区做语言或风格适配。
- **后台模板提示词无校验**：`TemplateItem.prompt` 可由运营直接编辑，缺少结构校验与预览测试。
