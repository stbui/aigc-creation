| 容器 | clientH | scrollH | 说明 |
| --- | --- | --- | --- |
| `.social-media-sidebarScroll` | 721 | 826 | 左栏内容区（1440×900 实测） |
| `.social-media-recipeBody` | 735 | 3573 | 右栏模板网格区 |

> 本站落地：左栏用既有 `.pk-form-scroll`（内部滚动），右栏新增 `.sc-showcase-body`（内部滚动），页面根不滚动。

## 10. 已知缺口

1. 参考站「生成中」「失败」两态未取证 —— 需要真实登录账号 + 可用模型通道 + 真实扣费。本站这两态由既有 `useResultGallery` / `useGenerateError` 链路覆盖，行为由本站后端决定，不照搬参考站。
2. 参考站「AI 帮写」按钮的填充行为未取证（需登录触发文本通道）。本站接入既有 `promptToolsApi.polish`（真实文本通道），失败如实报错、不拼接模板文案。
3. 参考站模板缩略图的**懒加载策略**未取证 —— 49 张卡一次性渲染在视口内，无 `IntersectionObserver` 证据。本站按「先渲染首屏 + `loading="lazy"`」实现。

## 13. 功能差异补正（2026-11-03 第二轮取证）

首轮实现后逐项复核参考站交互，发现三处功能差异并已补正。
本轮取证脚本：`probe-shoppable-fields.mjs` / `probe-local-echo.mjs`。

### 13.1 已选模板回显（原先缺失）

**参考站实测**（`social-media-selectedRecipe`）：切到「模板生成」后，左栏在模式卡下方出现一块灰底回显容器（364×82，底 `#f5f7f9`，圆角 12，内边距 12）：

| 态 | 内容 |
| --- | --- |
| 未选模板 | 「暂未选择模板」/「请从右侧选择合适的模板」 |
| 已选模板 | 缩略图（88px 宽竖图）+ 模板名 + 三拍文案 + 「换一个」文字按钮 |

「换一个」实测行为：**随机换成另一个模板**，左栏回显与右栏选中卡同步更新，分类仍停在「全部模板」。

**原实现**：模板选中后左栏无任何回显，用户切到模板模式看不到自己选了什么，也不知道「换一个」在哪。

**补正**：
- `ShoppableCarouselConfig.tsx` 新增 `selectedTemplate` / `onShuffleTemplate` props，按 `mode === 'template'` 渲染 `.sc-template-echo`（未选 / 已选两态）。
- `page.tsx` 新增 `shuffleTemplate`：从**当前分类之外**的模板池随机取一个（排除已选，避免原地不动），同步 `selectedTemplateId` 并保持模板模式。
- 样式 `sc-template-echo` 系列按实测尺寸落地，颜色换令牌（底 `--surface-soft`，「换一个」用 `--brand`）。

### 13.2 「AI 帮写」语义（原先错为文本润色）

**参考站实测**：未上传图片时点「AI 帮写」→ 提示 **「请先上传至少一张图片。」**；填入文案后再点，textarea 内容长度不变（11 → 11），无登录拦截。

说明它读的是**图片内容**（图文互转），不是润色已填文本 —— 与参考站商品主图页的「AI 分析」同源。

**原实现**：走 `promptToolsApi.polish`（润色已有文本），且无图时提示「请先填写商品卖点」。语义错了。

**补正**：改走 `promptToolsApi.imageToPrompt(first.id)`；无图时提示「请先上传至少一张图片」（与参考站逐字一致）；已填内容时不静默覆盖，先弹确认。

### 13.3 「社媒帖子发布文案」开关（原先是死开关）

**原实现**：该开关进了参数表，但 `buildPrompt` 没读它 —— 点了没反应。

**补正**（`shoppable_carousel.ts` 的 `buildPrompt`）：开关开启时，提示词追加「并在画面版式中安排一条可直接用于社媒发布的帖子文案（一句话，含商品核心卖点，使用<语言>）」。

本能力产出是**单张图片**（`modality: 'image'`），不能返回独立文字段，故把发布文案落进画面版式 —— 这样开关真实生效，且不新增一条与能力模态不符的产出通道。

优先级：`noText`（图片不加文字）**压过** `socialCaption` —— 两者语义互斥，用户显式要求不加字时不能再塞发布文案。

### 13.4 提示词标点修正

复核提示词全文时发现相邻分句粘连（「使用英文画面可包含…」「标签与平台水印并在…」）。已在 `buildPrompt` 中补齐标点，三种组合（socialCaption 开 / 关 / noText 开）实测输出均通顺。

## 16. 入口路由修正（2026-11-03）

**问题**：侧栏 / 顶部导航 / 工作台卡片 / 首页案例都通过 `toolPath()` 生成链接。
新增能力时**漏加映射**，`toolPath('shoppable_carousel')` 落到兜底分支
`/tools/<id>`，用户点进去看到的是通用工具页（`ToolPage`），而不是新做的复刻页。
表现为「页面设计根本不一致」——因为打开的确实不是这个页面。

**修正**：`frontend/src/lib/capabilities.ts` 的 `toolPath()` 增加一行：

```ts
if (id === 'shoppable_carousel') return '/shoppable-carousel';
```

验证：侧栏「AI 带货图文」href = `/shoppable-carousel`；工作台卡片 href 同；
点击后 `.sc-workspace` 存在（确实是新页面）。

> 这是新增独立工作台页时**必须同步**的一步：路由（`App.tsx`）+ 入口映射
> （`lib/capabilities.ts` 的 `toolPath`）缺一不可。只加路由不加映射，
> 页面存在但所有入口都指向通用工具页。
